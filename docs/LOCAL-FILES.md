# 이 브라우저에 파일 저장 (2026-11-11)

PDF · PPTX · 그림 파일을 교사 PC 브라우저(IndexedDB)에 원본 그대로 저장해요. 브라우저를 껐다 켜도, 새로고침해도 남고,
같은 브라우저의 여러 수업이 같은 파일을 함께 써요. 서버(Firebase Storage)에는 올리지 않아요(Spark 무료 요금제 그대로, PRD-v0.2 3-5).

## 1. 저장 구조

| 무엇 | 어디 | 모양 |
| --- | --- | --- |
| 파일 원본 | IndexedDB `navi-files`(로그인하면 `navi-files-{교사 UID}`)의 `files` | `{ id, name, type, size, at, blob }` |
| PDF 쪽 그림 | 같은 DB의 `pages` | `{ id: "{파일 id}:{쪽}", fid, n, blob }` (1600px JPEG, 올릴 때 한 번 그려요) |
| 수업(내 수업 · 지금 수업 · 끝나지 않은 수업 사본) | 예전 그대로(계정 또는 `navi-local`) | **파일 id만**: 수업 `file: { fid, kind, name }`, 장면 `fid` · `pg`(PDF 쪽 번호, `url: ""`), 자료 `fid` · `fname` · `mt` · PPTX면 `slides`(장 제목 · 글자) |

- **파일 id** = `f-` + 파일 내용의 SHA-256 앞 32자리. 같은 파일은 몇 번 올려도 한 번만 저장하고, 여러 장면 · 여러 수업이 그 id를 가리켜요.
- **blob 주소는 어디에도 저장하지 않아요.** 페이지를 열 때마다 파일 id로 IndexedDB에서 읽어 `URL.createObjectURL`로 새로 만들어요(`fileUrl`).
  주소는 안전한 형식(PDF · PNG · JPG · GIF · WebP · PPTX)으로만 만들어요. 그림은 이 네 형식만 받아요(SVG처럼 브라우저가 실행할 수 있는 파일은 받지 않아요).
- **계정(Firestore)** 에는 파일 id · 종류(pdf · pptx) · 이름만 가요. 규칙 `validFile`이 이 세 칸 · 모양만 받아요(`firestore.rules`, 운영 규칙에는 아직 배포하지 않았어요).
- 원본과 글자는 따로예요: 장면 이름 · 핵심 발화 · 교사 메모는 예전처럼 수업 문서에, 파일은 파일 저장소에.
- 파일 칸이 없는 예전 수업 · 예전 기록 · 예전 끝나지 않은 수업은 그대로 열려요(하위 호환).

## 2. 두 가지로 써요

| 쓰는 법 | 어디서 | 결과 |
| --- | --- | --- |
| 장면으로 만들기 · 새 수업 | 내 수업 → ‘내 수업 파일로 시작하기’ | 새 **내 수업**(저절로 저장). PDF는 쪽마다, PPTX는 슬라이드마다 장면 하나. 이름 · 핵심 발화 · 교사 메모는 예전처럼 고쳐요 |
| 장면으로 만들기 · 지금 수업 뒤에 | 수업 준비 → 장면 목록 아래 ‘+ PDF · PPTX에서 장면 더하기’ | 지금 내 수업의 마지막 장면 뒤에 더해요(한 수업 장면 100개까지) |
| 수업 자료로 첨부 | 수업 준비 → 수업 자료 ‘+ 자료’ → ‘파일’ | 고른 장면의 자료가 돼요. 장면 구조는 그대로 |

- PDF와 같은 장 수의 PPTX를 이어서 올리면, 예전처럼 PDF 쪽 그림에 PPTX의 장 이름 · 노트를 붙여요(새 수업을 만들지 않아요).
- 장 수 상한은 **파일 하나에 40장**(예전 그대로)이고, **100MB는 파일 크기 상한**이라 둘은 따로예요. 40장을 둔 까닭: 쪽마다 1600px 그림을 그려 저장하는 시간 · 메모리, 한 수업 장면 100개(규칙), 계정 문서 1MiB. 더 큰 파일은 나눠서 올려요.

## 3. PPTX는 어디까지 보이나

브라우저는 PowerPoint 파일을 그대로 그리지 못해요. 그래서 되는 것만 하고, 화면이 그대로 말해요.

| 읽어요 | 읽지 않아요 |
| --- | --- |
| 슬라이드 제목, 글자 6줄, 발표자 노트 | 그림 · 도형 · 표 모양 · 글꼴 · 색 · 배치 · 애니메이션 · 화면 전환 · 넣은 영상 · 소리 |

- 장면으로 만들면 글자 슬라이드로 보여요. 올릴 때 “그림 · 글꼴 · 배치 · 애니메이션은 옮기지 않아서 모양은 단순하게 보여요”라고 말해요.
- 원래 모양이 필요하면 PowerPoint에서 PDF로 내보내 함께 올려요(쪽 그림 + PPTX 노트).
- 자료로 첨부한 PPTX: 학생 화면에는 ‘PPTX · n장 · 글자만’ 카드(장 제목 목록)가 떠요. 원본은 교사 화면의 ‘PowerPoint로 열기’(내려받기)로 PowerPoint에서 열어요.

## 4. 한도와 저장 공간

- 파일 하나 100MB까지. 넘으면 저장하지 않고 “파일이 100MB보다 커요”라고 말해요(수업 · 자료가 생기지 않아요).
- 저장하기 전에 `navigator.storage.estimate()`로 남은 공간을 봐요(파일 크기 × 1.2 + 1MB). 모자라거나 실제 저장에서 `QuotaExceededError`가 나면 저장하지 않고 “저장 공간이 모자라요. ‘발표 설정 → 이 브라우저의 파일’에서…”라고 말해요.
- 처음 저장할 때 `navigator.storage.persist()`를 요청해요(공간이 모자랄 때 브라우저가 지우지 않게). 받아 줬는지는 발표 설정에 그대로 보여요.
- PDF를 못 읽으면 파일을 저장하지 않아요(못 쓰는 파일이 남지 않게).

## 5. 발표 설정 → 이 브라우저의 파일

- 이 사이트가 쓰는 공간 · 브라우저가 내준 공간, ‘지우지 않게 해 두었어요’ 또는 ‘지우지 않게 요청’ 단추.
- 파일마다 이름 · 크기 · **쓰는 수업**. 쓰는 수업이 있으면 ‘지우기’가 막혀요.
  쓰는 수업 = 이 브라우저가 아는 내 수업(계정 · 이 브라우저) · 지금 수업 · 끝나지 않은 수업 사본 · 최근 수업. 계정의 내 수업 목록을 받기 전에는 지우지 않아요.
- 수업을 지워도 파일은 남아요(다른 수업이 쓸 수 있어서). 다 쓰지 않게 된 파일만 확인 줄(“되돌릴 수 없어요”) 뒤에 지워요.

## 6. 파일이 없을 때

- 브라우저 데이터를 지웠거나, 다른 PC · 다른 브라우저에서 같은 계정으로 연 수업은 장면 글자는 보이고, 그림 자리에 “이 브라우저에 파일이 없어요. 파일을 다시 넣어 주세요.”라고 말해요.
- 수업 준비 위에 “이 수업이 쓰는 파일 n개가 이 브라우저에 없어요”와 ‘파일 다시 넣기’. 넣은 파일의 지문이 같을 때만 받아서 저장하고, PDF면 쪽 그림을 다시 그려요. 다른 파일이면 “내용이 달라요”.
- 휴대폰 리모컨 · 학생 화면으로 쓰는 다른 기기(`#stage`)는 “이 파일은 교사 PC에만 있어요.”

## 7. 교사마다 따로

- 로그인한 교사는 `navi-files-{UID}`, 로그인하지 않으면 `navi-files`. 공용 PC에서 교사 A가 로그아웃하고 B가 로그인하면 A의 파일은 목록에도 화면에도 없어요.
- 로그인이 확인되기 전(`storeOk`)에는 어느 파일 저장소도 열지 않아요(앞 사람 · 로그인하지 않은 칸의 파일이 잠깐이라도 보이지 않게).
- 로그인하지 않고 만든 수업을 ‘이 계정으로 가져오기’ 하면, 그 수업이 쓰는 파일도 계정 칸으로 **복사**해요(원본은 그대로).
- 화면에서 나누는 것이지 암호화는 아니에요(브라우저 개발자 도구로는 볼 수 있어요). `navi-local`과 같아요.

## 8. 학생 화면 · 다른 기기

- PC가 연 학생 화면 창은 교사 화면 페이지가 그리는 창이라 같은 주소를 써요: PDF 쪽 그림 · 그림 · PDF 자료가 교사 화면과 같게 보여요.
- 진행(장면 · 신호 · 자료 띄우기 · 끝내기)은 예전 그대로 글자로만 오가요. 파일은 휴대폰 · 다른 PC로 보내지 않아요.

## 9. 브라우저별 제약

| 브라우저 | 알아 둘 것 |
| --- | --- |
| Chrome · Edge(교탁 PC 권장) | 넉넉한 공간을 주고, 영구 저장 요청은 묻지 않고 사용 이력으로 받아 주거나 거절해요. 거절돼도 저장은 되고, 디스크가 모자랄 때만 지워질 수 있어요 |
| Firefox | 영구 저장을 요청하면 허락을 묻는 창이 뜰 수 있어요 |
| Safari(Mac · iPad) | 저장 공간이 더 작고, 사이트를 오래(약 7일) 쓰지 않으면 저장소를 지울 수 있어요. 교탁 PC로는 권하지 않아요 |
| 사생활 보호 창 | 창을 닫으면 지워져요. 저장소를 열 수 없는 브라우저면 예전처럼 ‘이 창에서만’ 쓰고, 다른 수업으로 바꾸기 전에 잃을 것을 알려 줘요 |
| 모든 브라우저 | 브라우저 데이터 지우기 · 다른 브라우저 · 다른 PC에는 파일이 없어요(6절). 정확한 공간은 발표 설정에 표시된 값이 기준이에요 |

## 10. 시험

| 시험 | 무엇을 |
| --- | --- |
| `tests/files.spec.js` | PDF · PPTX · 그림/PDF/PPTX 자료를 올리고 **브라우저를 닫았다 같은 데이터 폴더로 다시 실행**해도 그대로, 저장소에 blob 주소 없음, 교사 화면 · 학생 화면 같은 그림, 같은 파일 한 번만 · 복제한 수업도 같은 파일 · 쓰는 수업이 있으면 못 지움 · 확인 뒤 지우기, 수업 이름을 고친 바로 뒤 파일 고르기(저절로 저장과 겹침), 100MB 초과, 저장 공간 부족(남은 공간 · QuotaExceededError), 파일이 없을 때 안내와 다시 넣기 |
| `tests/library.spec.js`(에뮬레이터) | 계정에는 파일 id만, 휴대폰 “교사 PC에만 있어요”, 같은 브라우저의 교사 A · B 파일 분리, 다시 A로 로그인하면 그대로, A의 다른 PC는 “이 브라우저에 없어요” |
| `tests/rules.spec.js` | `file` 칸: id · 종류 · 이름만, 모양이 틀리면 거절, 파일 칸 없는 예전 수업도 받음 |
| 바꾼 시험 | `classroom.spec.js`: 올린 PDF는 이제 ‘이 브라우저에 저장’. `mylessons.spec.js` · `stage06.spec.js`의 ‘바꾸기 전에 확인’은 **파일을 저장할 수 없는 브라우저**(시험에서 파일 저장소만 막음 `noFileStore`)에서 같은 확인을 그대로 봐요. 저장할 수 있는 브라우저에서는 잃을 것이 없어서 묻지 않아요. `stage07.spec.js`의 ‘파일 고르기 → 올린 파일 빼기’ 회귀도 같은 조건으로 그대로 두고, 저장되는 브라우저의 회귀(‘파일 고르기 → 내 수업 저장 → 내 수업에서 삭제’)를 더했어요 |

## 11. 다음 과제

- 운영 Firestore 규칙에 `file` 칸 배포(교사 승인 뒤). 이번에는 **규칙을 먼저** 올리고 앱을 올려요: 규칙 없이 이 앱을 쓰면 파일로 만든 내 수업의 계정 저장이 거절되고 화면이 ‘저장 안 됨’이라고 말해요. 이 브랜치는 Production에 배포하지 않았어요.
- 다른 PC에서 쓰려면: 파일을 계정에 두는 서버 저장소(1단계-2, 비용 검토 필요) 또는 파일 내보내기 · 가져오기.
- PPTX 그림 · 배치 재현은 하지 않아요. 필요하면 PDF로 내보내 함께 올리는 길을 안내해요.
- 파일 목록에서 ‘쓰는 수업’으로 바로 가기, 오래 쓰지 않은 파일 정리 제안.
