# 수업 기록 관리 (2026-11-12, PR #14)

수업 기록은 **학생 개인 평가가 아니라 교사의 수업 관찰 기록**이에요. 장면마다 학급 전체에 대한 교사의 판단(신호등의 마지막 상태)을 하나씩 남기고,
수업 전체에서 각 상태의 장면 수를 세요. 학생 정보는 새로 모으지 않아요(이름 · 번호 칸이 없고, 보안 규칙도 그런 칸을 받지 않아요).

## 1. 기록 한 건(v3)

| 칸 | 뜻 |
| --- | --- |
| `title` · `grade` · `subject` · `cls` · `key` | 수업 제목 · 학년 · 교과 · 반 이름(발표 설정) · 어느 수업의 기록인지 |
| `startAt` · `endAt`(= `at`) | 수업을 시작한 시각 · 끝낸 시각(진행 날짜는 `endAt`). 예전 기록은 `startAt`이 없어요(지어내지 않아요) |
| `totalSec` · `plannedMin` | 실제 걸린 시간(장면별 시간의 합) · 계획한 분 |
| `scenes[]` = `{ id, label, min, sec, sig }` | 장면별 진행 시간(`sec`) · 계획(`min`) · **마지막 학급 이해도**(`sig`: `red` 다시 설명 · `yellow` 더 확인 · `green` 잘 이해 · `""` 신호 없음) |
| `sig` = `{ red, yellow, green }` | 각 상태가 마지막 신호인 **장면 수** |
| `questions[]` = `{ sid, label, text }` | 수업 중 남긴 질문 메모(어느 장면인지) |
| `again[]` | 다음 수업에서 보충할 내용(빨강 · 노랑 장면, 못 한 장면, 길어진 장면에서 만들고 교사가 고쳐요) |
| `text` | 교사 메모(끝난 화면 · 기록 화면에서 씀) |
| `used[]` · `usedTitles[]` | 학생 화면에 띄운 자료 |
| `events[]` | 누른 신호의 순서(같은 신호를 다시 누르면 지움) |
| `trashedAt` · `editedAt` | 휴지통에 넣은 시각(없으면 `null`) · 마지막으로 고친 시각 |
| `from` · `src` | 계정에 올라오기 전 이 브라우저의 id · 어디서 왔는지(`pc` 이 계정의 PC · `old` 로그인 전에서 가져옴 · `here` 이 브라우저에만 있던 것) |

- **id**: 수업 시작 시각으로 만들어요. 이 브라우저는 `local-{시작 시각 36진수}`, 계정은 `r-{같은 값}`. 끝내기 · 새로고침 · 다시 연결 · ‘기록 저장하고 끝내기’가 같은 기록을 다시 써도 **한 건**이고, 같은 수업을 다시 하면 시작 시각이 달라 **따로** 남아요. 예전 id(`local-…`가 아닌 것)는 그 id로 만든 고정 값 `r-x…`를 써요.
- 예전 기록(v1 `rc` · v2)은 그대로 읽어요. 신호 수 · 질문은 기록 화면이 늘 읽던 방식(`recSig` · `recQs`)으로 옮기고, 없는 값(시작 시각 · 장면 id)은 비워 둬요.

## 2. 어디에 저장하나

| 상황 | 저장 |
| --- | --- |
| 로그인하지 않음 | 이 브라우저 `navi-local`(예전과 같아요). 화면이 “이 브라우저에만”이라고 말해요 |
| 구글로 로그인한 교사 PC | 먼저 이 브라우저 `navi-local-{UID}`, 그다음 계정 `teachers/{UID}/records/r-…`. 서버가 확인한 뒤에만 “계정에 저장했어요” |
| 인터넷이 끊김 | 이 브라우저에는 저장되고, 4초 안에 서버 답이 없으면 “인터넷이 끊겨 아직 계정에 저장하지 못했어요. 이 브라우저에는 저장했고, 다시 이어지면 계정에 저장해요” |
| 창을 닫았거나 새로고침함(아직 계정에 못 감) | 다음에 이 계정으로 열 때(그리고 인터넷이 돌아올 때 · 30초마다) 이 브라우저의 기록을 다시 보내요. 같은 id라 중복이 없어요 |
| 저장이 거절됨 | “계정에 저장하지 못했어요. 이 브라우저에는 저장돼 있어요” + ‘다시 저장’ |
| 휴대폰 리모컨 | 기록을 쓰지 않아요(교사 PC가 한 번만 써요, 예전과 같아요) |

- 계정의 기록은 다른 교사 · PIN 휴대폰 · 로그인하지 않은 사람이 읽거나 고칠 수 없어요(`firestore.rules` `records`).
- 같은 계정으로 로그인한 다른 PC에서도 보이고, 한쪽에서 고친 메모가 다른 쪽에 이어져요.
- 기록 화면은 계정의 최근 30건을 실시간으로, 그 뒤는 ‘기록 더 보기’로 30건씩 불러와요(`endAt` 순). 휴지통은 따로(`trashedAt` 순) 불러와요. 두 조회 모두 한 칸 조건이라 복합 색인이 필요 없어요.

## 3. 기록 화면

- 탭: 이 수업 · 전체 · 휴지통.
- 찾기: 수업 제목 검색, 기간(최근 7 · 30 · 90일), 학년, 교과, ‘보충할 장면이 있는 기록만’. 계정의 기록이 더 남아 있으면 “불러온 기록 안에서 찾아요”라고 말해요.
- 줄마다: 날짜 · 제목 · 걸린 시간 · **보충할 장면 수**(빨강 · 노랑) · 신호별 장면 수 · 저장된 곳(계정에 저장됨 · 이 브라우저에만 · 계정에 저장하는 중 · 인터넷을 기다리는 중).
- 펼치면: 시작 · 끝 시각, **장면별 이해도와 시간 표**(빨강 · 노랑 장면은 바탕색, 신호는 색 + 아이콘 + 글자), 수업 흐름 띠, 다시 지도할 것, 질문 메모, 보여 준 자료, 교사 메모.
- 고치기: 교사 메모는 늘, ‘다시 지도할 것 · 질문 메모 고치기’를 누르면 다시 지도할 것(한 줄에 하나) · 질문 메모 글을 고쳐요. 장면 · 시간 · 신호는 고치지 않아요(수업 중 기록이라서).
- 같은 수업을 다시 하면 기록은 따로 남아요(위 id).

## 4. 휴지통(30일)

- ‘휴지통으로’(확인 줄) → 목록에서 빠지고 휴지통에. 삭제한 날과 “N일 뒤 영구 삭제”를 보여 줘요.
- 30일 안에 ‘되살리기’ → 같은 id · 같은 내용(휴지통 표시만 비워요).
- **30일이 지난 휴지통 기록은 수업 내비를 열 때 지워요**(계정: 이 계정으로 기록을 불러올 때, 이 브라우저: 이 브라우저에서 열 때). 정해진 시각에 저절로 지우는 서버 일은 쓰지 않아서, 앱을 열지 않으면 그 사이에는 남아 있어요. 화면도 그렇게 말해요.
- 보안 규칙: 휴지통에 넣은 시각은 서버 시계 ± 10분 안이라야 하고, **영구 삭제는 휴지통에 30일이 지난 기록만** 돼요(실수로 바로 지울 수 없어요).
- 서버가 정해진 시각에 지우게 하려면: Firestore TTL 정책(콘솔 · gcloud 설정, 만료 뒤 보통 24시간 안에 지움, 날짜 형식 칸 필요 — https://firebase.google.com/docs/firestore/ttl) 또는 예약 실행 함수가 있어야 해요. 둘 다 운영 설정 변경이라 이번에는 하지 않았고, Spark 요금제에서 쓸 수 있는지도 확인하지 않았어요.
- 휴지통은 **수업 기록에만** 있어요. 내 수업 지우기는 예전 그대로예요.

## 5. 예전 기록 옮기기

| 어디의 기록 | 어떻게 |
| --- | --- |
| `navi-local`(로그인 전) | 예전 그대로 ‘이 계정으로 가져오기’(확인 줄)를 고를 때만 이 계정 칸(`navi-local-{UID}`)에 사본을 넣고 원본에 `claimedBy`를 적어요(원본은 지우지 않아요) |
| `navi-local-{UID}`에만 있는 기록(이번 버전 전에 만든 것 · 가져온 것) | 기록 화면의 “이 브라우저에만 있는 기록 N건” → **‘계정에 저장하기’를 누를 때만** 계정에 올려요. 이 브라우저의 기록은 지우지 않고, 올라간 것에 표시(`srvAt`)만 더해요 |
| 이번 버전에서 이 계정의 PC로 끝낸 수업 | 저절로 계정에(위 2절) |

- 하나씩 올리고, 실패한 것은 그대로 남아요(“N건 중 M건을 계정에 저장했어요. 나머지는 이 브라우저에 그대로 있어요. 다시 눌러 주세요”). 다시 누르면 남은 것만 올라가고, 같은 id라 두 번 생기지 않아요.
- 다른 계정과 섞이지 않아요: 계정마다 다른 칸(`navi-local-{UID}`)에서만 고르고, 계정에는 그 UID 자리에만 써요.
- 가져온 기록이 계정에 올라간 뒤에는 ‘가져오기 되돌리기’를 숨겨요(계정의 기록은 휴지통으로 지워요).
- 변환 전후 비교는 시험이 봐요(제목 · 끝난 시각 · 걸린 시간 · 장면별 시간과 신호 · 신호 수 · 질문 · 다시 지도할 것 · 교사 메모 · 자료).

## 7. 운영 배포 전 주의

- 운영 Firestore 규칙에 `records`를 넣어야 계정 저장이 돼요(교사 승인 뒤, **규칙 먼저**). 규칙 없이 앱만 올리면 계정 저장이 거절되고 화면이 “계정에 저장하지 못했어요 · 이 브라우저에는 저장돼 있어요”라고 말해요(기록은 이 브라우저에 남아요).
- PR #12(`file`) · PR #13(세션 `vid`) 규칙도 아직 운영에 없어요. 함께 올릴 때 순서를 지켜요. 지금 운영 규칙과의 비교 · 배포 순서는 `docs/STABILITY.md` 7절이에요.
- Spark 무료 한도: 기록 1건 = 쓰기 1번(+ 고칠 때마다 1번), 기록 화면 = 최근 30건 읽기 + 휴지통 읽기. 교사 몇 명이 쓰는 동안에는 한도 안이에요.
