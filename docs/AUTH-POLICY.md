# 가입 · 로그인 · 계정 정책 (2026-11-11 확정, 아직 실제 배포 안 함)

교사는 **운영자 승인 없이 구글 계정으로 가입**해 수업 내비를 써요. 대신 계정마다 자기 자리(`teachers/{UID}`)만 읽고 쓰고,
휴대폰 연결은 지금처럼 **교사 PC가 허용한 기기만** 들어와요. 이 문서는 2026-11-10의 ‘시범 교사 목록’ 변경안(PR #10 첫 커밋)을 대신해요.

## 1. 정책

| 항목 | 정책 |
| --- | --- |
| 가입 | 구글 계정이면 누구나 승인 없이 가입 · 사용. 예전 시범 교사 목록(`allowed/{UID}`)은 쓰지 않아요(읽지도 않아요) |
| 휴대폰 QR · PIN | 가입한 교사 누구나 써요. PIN 휴대폰은 교사 PC가 허용해야만 들어오고, 그 수업(run) · 3시간만 읽어요 |
| 로그인 유지 | 로그인 화면의 **‘이 브라우저에서 로그인 유지’**(기본 켜짐). 켜면 브라우저를 닫았다 열어도 로그인, 끄면 그 탭에서만 |
| 시간 제한 | 없음(예전 ‘같은 날 12시간’ 규칙을 없앴어요). 로그아웃은 교사가 직접 |
| 공용 PC | 기록 화면의 “공용 PC라면 기록을 확인한 뒤 로그아웃해 주세요” 안내 · 로그인 화면의 “공용 PC라면 체크를 풀어요” |
| 수업 중 로그아웃 | 확인 줄: ‘기록 저장하고 로그아웃’(수업을 끝내 기록을 남긴 뒤) · ‘계속 수업’ |
| 표시 이름 | 처음 로그인하면 한 번 물어요. 구글 계정 이름이 기본값, 발표 설정에서 바꿔요. 학교명은 묻지 않아요(규칙은 선택 칸으로만 받아요) |
| 데이터 분리 | 수업 · 설정 · 세션 · 표시 이름은 `teachers/{UID}`, 이 브라우저의 기록 · 고친 예시는 `navi-local-{UID}`. 다른 회원의 것은 읽지도 고치지도 못해요 |

## 3. 보안 규칙 (`firestore.rules`)

| 누가 | 할 수 있는 것 | 못 하는 것 |
| --- | --- | --- |
| 가입한 교사 본인(구글, UID 같음) | 자기 수업 내용 · 설정 · 준비 상태 · 세션 · 명령 처리 표시 · 허용 기기 · 표시 이름 읽기 · 쓰기, 자기 설정의 PIN 자리 열기 · 닫기 · 요청 답하기 | 다른 교사의 모든 문서, 정해진 칸 밖(학생 이름 등), 지우기(세션 · 수업 · 표시 이름) |
| 다른 교사 · 새로 가입한 계정 | 자기 자리만 | 남의 자리 전부, 남이 맡은 PIN 닫기 · 거절 · 요청 보기 |
| 같은 UID의 다른 로그인(익명 · 이메일) | 없음(계정 본인 확인 = 구글 로그인) | 자기 UID 자리조차 |
| 익명 휴대폰(허용 전) | PIN 자리 하나 읽기, 열린 자리에 요청 하나 | 교사 문서 전부 |
| 익명 휴대폰(교사 PC가 허용) | 그 수업(run) · 시간 안에 수업 내용 · 설정 · 준비 상태 · 그 세션 읽기, 자기 명령 문서 쓰기, 시작 요청 · ping | 수업 문서 쓰기, 표시 이름 · 다른 세션 · 다른 교사 읽기, run이 바뀐 뒤 읽기 |
| 로그인 안 함 | 없음 | 전부(PIN 자리 읽기도) |

PIN 요청 남용 방어(그대로 둔 것): 열린 동안(3분, 규칙 상한 5분)만 · 기다리는 요청 3개 · 한 번 열 때 20개 · 거절된 익명 계정은 그 PIN에 다시 못 옴 ·
자리에는 교사 id 대신 SHA-256 해시 · 교사 PC가 허용해야만 기기 문서가 생김 · 허용은 그 수업(run) · 4시간 상한 · 수업이 끝나면 run이 바뀌어 남은 기기도 막힘.

새로 더한 방어(승인 목록을 없앤 만큼): **한 계정은 자기 설정(`lessons/settings.pin`)의 PIN 자리만 열거나 다시 열어요.** 계정 하나가 빈 PIN 여러 개를 맡아 두지 못해요.
앱은 PIN을 바꿀 때 설정을 먼저 저장하고 그 PIN을 열어서(`changePin` → `holdPin`) 화면 흐름은 그대로예요.

남는 위험(규칙으로 못 막는 것, docs/UX-1-1.md 10 · 11-1과 같아요):
- 구글 계정을 여러 개 만들거나 설정의 PIN을 바꿔 가며 PIN 자리를 잡는 방해: 들어오는 위험은 없고(허용 필요), 수업 전이면 PC가 새 PIN으로 옮겨요. 바꿀 때마다 쓰기 2개가 들어 하루 쓰기 한도(2만)에 먼저 걸려요.
- 자유 가입이라 누구나 자기 자리에 문서를 만들 수 있어요(무료 사용량 · 저장 공간 소모). Spark라 요금은 없지만 그날 서비스가 멈출 수 있어요. 여러 교사가 쓰기 전에 App Check(감시만 → 강제)와 사용량 알림을 정해요.

## 4. 로그인 유지 (`public/claude-shim.js`)

| 체크 상자 | Firebase 저장소 | 새로고침 | 새 탭 · 창 | 브라우저 다시 열기 | 탭 복원 · 복제 |
| --- | --- | --- | --- | --- | --- |
| 켬(기본) | 브라우저 저장소(IndexedDB) | 로그인 | 로그인 | 로그인 | 로그인 |
| 끔 | 그 탭의 저장소(sessionStorage) | 로그인 | 로그인 전 | 로그인 전 | 로그인이 남아요(크롬이 탭 저장소를 되살려서) |

- 고른 값은 이 브라우저의 `localStorage`에 `navi-keep-login`(1 · 0)으로 남고, 다음에 페이지를 열 때 그 저장소에서만 로그인을 찾아요. 로그인 화면의 체크 상자는 늘 켜진 채로 시작해요.
- ‘로그인함’ 표시(`navi-signed-in`)도 로그인과 같은 저장소에만 둬요. 예전 12시간 기록(`navi-signed-at`)은 읽지도 쓰지도 않아요.
- PIN 휴대폰(익명)은 그 휴대폰의 브라우저 저장소에 둬요(개인 기기, 예전과 같아요).
- 한 브라우저에서 두 교사가 동시에(한 명은 유지, 한 명은 이 탭만) 쓰면, 다음에 여는 탭은 마지막에 고른 쪽을 따라가요. 공용 PC는 끝나면 로그아웃해요.

## 5. 표시 이름 (`teachers/{UID}/profile/me`)

- `{ v, name, at }`(학교명 `school`은 선택 칸, 지금 화면에서는 묻지 않아요). 이름 1–40자.
- 서버가 ‘없다’고 답했을 때만 교사 PC의 수업 준비 화면에 한 줄로 물어요(막지 않아요). 서버에 닿지 못하면 묻지 않아요.
- 교사가 ‘이 이름으로 시작’ · ‘저장’을 누를 때만 써요. 수업을 맡는 것(hub)과 상관없는 계정 정보라 `db.held`를 거치지 않아요.

## 6. 기존 데이터 · 로컬 기록

- 운영 Firestore의 `allowed/{시범 교사 UID}` 문서는 지우지 않아요. 새 규칙에서는 아무도 읽지 않는 문서로 남아요(지우려면 교사 승인 뒤).
- 운영 교사의 수업 · 설정 · 세션은 같은 경로(`teachers/{UID}`)라 그대로 이어져요.
- 이 브라우저의 기록: 로그인하지 않은 칸 `navi-local`, 계정 칸 `navi-local-{UID}`, ‘이 계정으로 가져오기’(사본 + `claimedBy`)는 바꾸지 않았어요(`control.spec.js`의 교사별 기록 · 이 계정으로 가져오기 시험, 이번에 바꾸지 않았어요).

## 7. 배포 순서(승인 뒤)

1. 지금 운영 규칙을 읽어 사본으로 저장(`docs/backup/`).
2. 시험 프로젝트에서 실제 기기 시험(`docs/FIREBASE-TEST-ENV.md`).
3. **앱(이 PR 병합) → 곧바로 규칙 배포.** 지금 운영 규칙은 PIN 자리를 시범 교사 목록으로 막아서(`docs/PREVIEW-PR5.md` 기록), 앱만 먼저 나가면 목록 밖 교사의 PIN 열기가 거절돼요(서버에 남는 것은 없어요).
4. 배포 뒤 규칙을 다시 읽어 저장소와 같은지, 새 구글 계정으로 수업 한 번 · PIN 휴대폰 한 번을 확인해요.

되돌리기: 1의 사본으로 규칙을 다시 배포, 앱은 Vercel 이전 배포로. 데이터는 바꾸지 않아서 되돌릴 것이 없어요.

### 시험 안정성 (PR #10 첫 커밋에서 그대로)

- PIN 자리는 모든 교사가 함께 쓰는 곳이라, 동시에 도는 시험끼리 PIN이 겹치지 않게 **시험 작업자마다 겹치지 않는 PIN 구간**(1000–2999 · 3000–4999 · 5000–6999 · 7000–8999)을 주고 기기마다 40개씩 나눠 줘요(앱의 `newPin`이 에뮬레이터에서만 이 구간을 써요). 9000–9999는 어떤 시험에도 주지 않아 ‘아무도 열지 않은 PIN’ 확인에 써요.
- 시험이 끝나면 그 시험이 연 브라우저를 닫고, 그 시험의 교사가 맡았던 PIN 자리를 지워요.
- 연결 코드는 **한 페이지에서 한 번만 열어요**(`claude.use("db")`를 다시 불러도 같은 결과).
- `readDoc`(다른 기기에서 다시 읽기)은 45초 안에 값이 오지 않으면 그동안 받은 소식을 담아 실패해요(멈춘 까닭이 남게).

**저장 → 다른 기기에서 읽기가 가끔 멈추던 까닭(2026-11-10, 에뮬레이터 결함)**

`roundtrip.spec.js` 첫 시험이 반복 실행에서 16번 중 1–4번, 첫 수업 저장에서만 멈췄어요(main에서도 드물게). Firestore SDK 기록을 켜고 재현해 보니 순서는 이랬어요.

| 05.601 | PC가 수업 내용(`lessons/deck`, 큰 문서)을 저장, 서버 확인 |

그 뒤로 휴대폰의 이 문서는 다음 저장 때까지 ‘없음’이에요(새로 감시를 걸어도 같아요). 실제 Firestore는 ‘여기까지 다 보냈다’는 시각 안의 변경을 모두 먼저 보내도록 되어 있어서 이 순서가 생기지 않아야 해요. 그래도 실제 기기 시험에서 따로 확인해요(`docs/FIREBASE-TEST-ENV.md` 4).
고친 것: 이 시험은 휴대폰의 첫 묻고 답하기가 서버에서 끝난 뒤(다음 물음까지 20초) 저장해요. 비교하는 내용과 시간 제한은 그대로예요. PIN 충돌과는 상관없었어요(PIN을 쓰지 않는 시험이에요).
