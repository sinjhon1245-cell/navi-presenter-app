# 교사 PC 새로고침과 수업 화면(TV) 창 (2026-11-19, PR #26)

4단계 실제 40분 수업 검증의 MEDIUM 2. 교사 PC를 새로고침하면 수업 화면 창이 닫히고, ‘이어서 하기’가 1280×720 새 창을 교사 화면 쪽 (0, 0)에 열었어요. 교사는 그 창을 TV로 다시 옮기고 ‘전체 화면’을 다시 눌러야 했어요. 상태 표시는 정확했어요(‘켜짐’은 새로 연 창).

## 구조

수업 화면 창은 교사 화면이 `window.open("", "navi-stage")`으로 연 **빈 창**이고, 교사 화면이 그 문서에 직접 그려요(`renderStageWin` → `paint`). 창 안에는 우리 스크립트가 없었고, 클릭 · 키 손잡이도 교사 화면이 붙였어요. 그래서 교사 화면이 새로고침되면 그 창을 그릴 주인이 없어서 `beforeunload`에서 닫았어요.

## 기술 판단: 창을 그대로 둘 수 있어요(Chrome · Edge)

실험(`window.open` 빈 창에 그린 뒤 교사 탭 새로고침, Chrome 157 · Edge 157 창 모드, 각 2번):

| 확인한 것 | Chrome | Edge |
| --- | --- | --- |
| 새로고침 뒤 창이 남아 있음 | 예 | 예 |
| 창 안에 넣은 작은 스크립트(창 자신의 것)가 살아서, 새 페이지(`window.opener`)에 창을 넘겨줌 | 0.22초 | 0.23초 |
| 전체 화면 유지 | 예 | 예 |
| 옛 페이지가 붙인 클릭 · 키 · 메시지 손잡이가 다시 불림 | 아니요(사라짐) | 아니요 |
| 두 번째 새로고침도 넘겨받음 | 예 | 예 |
| 교사 탭을 닫으면 창이 스스로 닫힘 | 예 | 예 |

이름으로 창을 다시 찾지 않아요(`window.open("", 이름)`은 창이 없으면 새 창을 만들 수 있어서). 창이 자기 `opener`(같은 탭)에 스스로 넘겨줘요. 그래서 다른 탭 · 다른 사이트가 이 창을 가져갈 수 없어요.

Firefox · Safari는 시험하지 않았어요(교실 PC는 Chrome · Edge 기준). 다른 브라우저에서 넘겨받지 못하면 예전처럼 ‘이어서 하기’가 새 창을 열어요.

## 바뀐 것

1. **창을 열 때** 그 창에 작은 스크립트(`STAGE_WATCH`)를 넣어요. 0.5초마다:
   - 같은 탭에 이 앱 페이지가 있으면 `opener.__naviAdopt(창)`을 불러요(이미 그 페이지의 창이면 아무것도 하지 않아요).
   - 교사 탭이 닫혔거나 다른 사이트로 갔으면(3초 이어서) 창을 닫아요. 학생에게 지난 화면이 남지 않게 해요.
2. **새로고침할 때(`pagehide`)** 창을 닫지 않아요. 창 위쪽에 ‘교사 화면과 다시 연결하는 중이에요’를 띄워요(1.2초 뒤에 나타나서 바로 이어지면 깜박이지 않아요). 새로고침 중에 옛 페이지가 창을 다시 가져가지 않게 `__naviAdopt`를 지워요.
3. **새 페이지**는 누구의 페이지인지 안 뒤에(`ownerTag`, 계정 확인 뒤) 창을 받아요(`adoptStage`).
   - 그 창이 같은 계정의 것(`data-navi-owner`)일 때만 받아요. 로그아웃 · 다른 계정 · 로그인 안 함이면 받지 않고 닫아요.
   - 클릭 · 키 · 영상 메시지 손잡이를 새로 붙이고, 지금 버전의 스타일로 바꿔요.
   - **받은 창은 바로 그리지 않아요(held).** 끝나지 않은 수업이 있으면 교사가 고를 때까지 마지막 장면과 ‘다시 연결하는 중’을 그대로 둬요. 이어서 하기 전의 페이지는 아직 그 수업을 갖고 있지 않아서, 그리면 ‘수업 전’ 화면으로 바뀌기 때문이에요.
4. **교사가 고르면** 그 창에 다시 그려요. 새 창은 열지 않아요.

   | 고른 것 | 그 창 |
   | --- | --- |
   | 이어서 하기 | 지금 장면(그사이 휴대폰이 넘긴 것까지) |
   | 지금까지 기록 저장하고 끝내기 | ‘수업 끝’(평소 수업을 끝낸 뒤와 같아요) |
   | 기록 없이 버리기 | 수업 전 화면 |
   | 끝나지 않은 수업이 없음(준비 중 새로고침) | 바로 지금 화면 |

5. **로그아웃(공용 PC)** 은 그 창을 바로 닫아요(`stageQuit`). 앱의 단추를 거치지 않고 로그인이 풀린 새로고침도 계정이 달라서 받지 않고 닫아요.
6. **같은 브라우저의 다른 탭**이 수업을 가져가면(`lostHub`), 이 탭은 그 창을 다시 받지 않아요(`stageLetGone`).

## 화면이 말하는 것

‘다시 연결 전’은 ‘켜짐’이 아니에요. 교사 화면이 다시 그리기 전에는 연결됐다고 말하지 않아요.

| 곳 | 창을 다시 받기 전 · 고르기 전(held) | 다시 그린 뒤 |
| --- | --- | --- |
| 수업 화면(TV) | 마지막 장면 + 위쪽 ‘교사 화면과 다시 연결하는 중이에요’ | 지금 장면, 안내 없음 |
| 끝나지 않은 수업 알림 | ‘수업 화면(TV)은 열린 그대로예요. ‘이어서 하기’를 누르면 그 창에 지금 장면이 나와요.’ | 없음 |
| 옆 메뉴 · 수업 준비 줄 | 수업 화면 · 다시 연결 전 | 수업 화면 열림 |
| 휴대폰(`lessons/hub.stage`) | ‘수업 화면 · 열려 있지 않아요’ | 없음 |

창이 이미 닫혀 있으면 알림이 ‘수업 화면(TV) 창은 닫혀 있어요. ‘이어서 하기’를 누르면 새로 열려요. TV로 옮긴 뒤 ‘전체 화면’을 눌러 주세요.’라고 미리 말해요. 발표 설정에서 모니터 목록을 허용해 둔 브라우저면(묻지 않고 확인되는 경우만), 새로고침 뒤에도 고른 모니터에 열고 ‘(2번 모니터)’라고 말해요.

## 그대로인 것 · 한계

- 학생 화면에는 교사 노트 · 다음 장면이 없어요(시험이 확인해요). ‘다시 연결하는 중’ 한 줄만 더해져요.
- 수업 데이터 · 기록 · 저장 구조 · Firestore 규칙은 그대로예요. 기록은 한 번만 남아요.
- 전체 화면은 브라우저 규칙상 수업 화면 창에서 사람이 눌러야 켜져요. 창을 그대로 두면 다시 누를 필요가 없지만, 창이 닫혔다 새로 열리면 예전처럼 ‘전체 화면’을 한 번 눌러야 해요.
- 영상: 새로고침하는 동안에도 TV의 영상은 멈추지 않아요(창이 그대로라서). 다시 그릴 때 같은 영상 창은 그대로 두고(`keepFrame`), 재생 상태는 다시 물어서 알아요. 다만 교사 화면이 기억하던 ‘멈춘 곳’(`vidPos`)은 새로고침하면 사라져요(예전과 같아요).
- 교사가 고르지 않고 두면 TV는 마지막 장면과 ‘다시 연결하는 중’을 계속 보여 줘요. 수업이 멈춘 그 자리라서 다른 수업 내용이 보이지는 않아요.
- 교사 PC 브라우저 전체가 꺼지면 창도 함께 꺼져요(지킬 창이 없어요).

## 시험

- `tests/stage-keep.spec.js`(로그인 없이, PC 두 크기): 새로고침 뒤 같은 창 · 자리 · 크기, 마지막 장면 + 안내, 교사 화면 ‘다시 연결 전’ → 이어서 하기 → 새 창 없이 지금 장면, 노트 없음, TV 창 키 한 번 = 한 장면, 두 번째 새로고침, 끝까지 가면 기록 하나. 새로고침 뒤 끝내기 → ‘수업 끝’, 버리기 → 수업 전. 수업 전(준비 중) 새로고침 → 바로 수업 전 화면 · ‘열림’, 수업 시작도 그 창. 창을 직접 닫으면 알림 → 다시 열기 → 닫힌 채 새로고침하면 알림이 ‘새로 열려요’ → 이어서 하기가 새 창에 지금 장면 → 그 창은 다음 새로고침에 그대로. 교사 탭 닫기 · 다른 사이트로 가기 → 창이 스스로 닫힘.
- `tests/class-screen.spec.js`(에뮬레이터): 로그인한 교사 PC 새로고침 → 그 창 그대로, 그사이 휴대폰은 ‘열려 있지 않아요’ · 휴대폰이 넘김 → 이어서 하기 뒤 그 장면, 끝내기 · 로그아웃하면 그 창이 바로 닫힘. 앱 단추 없이 로그인이 풀린 새로고침은 그 창을 받지 않고 닫음.
- 페이지를 다시 연 뒤 ‘이어서 하기’가 새 창을 연다고 보던 시험 4개(`live` · `library` · `realtime` · `progress`의 `start()`)는 그 창이 그대로 지금 장면을 보여 주는지 보도록 바꿨어요(확인하는 장면 · 자료는 그대로). 강제로 닫은 탭 대신 새 탭에서 이어서 하는 시험(`control`)은 예전처럼 새 창을 열어요.

재현: `stage-keep` 시험 3개는 고치기 전 코드에서 실패했어요(새로고침하면 창이 닫힘).
