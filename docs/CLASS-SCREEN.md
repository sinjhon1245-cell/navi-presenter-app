# 수업 화면은 선택 · 모바일 리모컨에서 시작 (2026-11-13)

교사 PC에서 수업 자료를 준비하고 수업 화면을 미리 열어 둔 뒤, 모바일 리모컨에서 ‘수업 시작’을 누르면 교사 화면과 수업 화면이 함께 수업으로 바뀌어요.
수업 화면은 **있으면 쓰는 화면**이에요. 없어도 시작하고, 수업 전이든 수업 중이든 교사 PC에서 언제든 열 수 있어요.
바탕: `docs/NEXT-STUDENT-SCREEN.md`(시험 브랜치에 남긴 기록). 진행 엔진(`sendOwn` → `db.held`, 시작 요청 `sta-` → `go-`, `hub.pc`)과 보안 규칙은 바꾸지 않았어요.

## 1. 화면 이름

| 이름 | 무엇 | 예전 이름 |
| --- | --- | --- |
| 교사 화면 | 노트북 · 교탁 PC. 수업 자료와 진행을 관리해요 | 그대로 |
| 수업 화면 | 전자칠판 · TV. 학생에게 보여 주는 화면 | 학생 화면 |
| 모바일 리모컨 | 휴대폰. 수업 시작과 장면 이동을 해요 | 휴대폰 리모컨 |

- 단추 · 상태 · 설정 · 안내 · 오류 문구와 수업 화면 창의 제목(‘수업 내비 · 수업 화면’)까지 바꿨어요. 기기 자체를 말할 때는 ‘휴대폰’을 그대로 써요(‘휴대폰 연결’, ‘이 휴대폰’).
- 예전에 ‘수업 화면’이라고 부르던 다른 것은 겹치지 않게 바꿨어요: 수업 중 교사 화면 · 리모컨의 밝기 단추 ‘수업 화면 밝게/어둡게’ → ‘화면 밝게/어둡게’, 설정의 ‘수업 화면 (교사 화면 · 휴대폰 리모컨)’ → ‘수업 중 교사 화면 · 모바일 리모컨’, PIN 연결 직후 ‘수업 화면을 여는 중이에요…’ → ‘리모컨을 여는 중이에요…’.
- 코드 안의 `stage` · `stageWin` · `hub.stage` 같은 이름은 그대로예요. 예전 문서(SPEC · DESIGN-SYSTEM · 리뷰 기록)는 예전 이름 그대로 남아 있어요.

## 2. 바뀐 동작

| 어디 | 예전 | 지금 |
| --- | --- | --- |
| 모바일 리모컨 · 시작 전 | 교사 PC · 수업 자료 · **학생 화면** 세 가지가 되어야 ‘수업 시작’ | **교사 PC · 수업 자료** 두 가지면 시작. 수업 화면 줄은 상태만(‘열려 있어요’ / ‘열려 있지 않아요 · 없어도 시작할 수 있어요’), 열려 있지 않으면 “수업 화면은 교사 PC에서 ‘수업 화면 열기’를 누르면 열려요. 수업 중에도 열 수 있어요.” |
| 모바일 리모컨 · 확인 줄 | “PC · 학생 화면 · 이 휴대폰에서 함께 시작할까요?” | 수업 화면이 열려 있으면 “교사 화면 · 수업 화면 · 이 리모컨에서 함께 시작할까요? / 첫 장면이 수업 화면에 바로 보여요.”, 없으면 “교사 화면과 이 리모컨에서 시작할까요? / 수업 화면은 열려 있지 않아요. 수업 중에도 교사 PC에서 열 수 있어요.” 확인 줄이 열려 있는 동안은 위의 ‘여는 방법’ 안내를 숨겨요(같은 말을 두 번 하지 않게) |
| 교사 PC · 휴대폰 요청 처리 | 수업 화면 창이 없으면 `stage`로 거절(“PC에서 학생 화면을 먼저 열어 주세요”) | 거절하지 않아요(`startWhy`에서 뺌). 휴대폰 요청으로 시작할 때는 **새 창을 열지 않아요**(`start(true)`) — 사람이 PC에서 누르지 않은 창 열기는 팝업 차단에 걸리거나 원하지 않는 곳에 창을 띄우니까요 |
| 교사 PC · 수업 준비 화면 | ‘시작 전 확인’의 ‘학생 화면 확인 전 · 모니터 확인 · 창 열어 보기’ → 발표 설정으로 이동 | ‘**수업 화면 열기** · 없어도 시작할 수 있어요’를 누르면 바로 창이 열리고 ‘수업 시작 전’으로 기다려요. 열린 뒤에는 ‘수업 화면 열림’(누르면 그 창을 앞으로). 모니터 설정이 겹칠 때만 발표 설정으로. 왼쪽 아래 상태 줄(단추가 아님)은 ‘수업 화면 · 열려 있지 않아요’ / ‘수업 화면 열림’ |
| 교사 PC · 창 하나 | 다시 누르면 같은 이름의 창을 처음부터 다시 그렸어요(재생 중 영상이 다시 시작될 수 있음) | 이미 열려 있으면 **새로 만들거나 다시 그리지 않고** 앞으로만 가져와요 |
| 교사 PC · ‘수업 시작’ | 발표자 보기면 수업 화면 창을 함께 열어요 | 그대로(교사가 PC에서 직접 누른 것이라). 창이 막히거나 닫혀도 수업은 그대로 진행돼요 |
| 교사 화면 · 수업 중 수업 화면이 닫혀 있을 때 | 주황 경고 “학생 화면 창이 닫혀 있어요. TV에 아무것도 보이지 않아요.” | 차분한 안내 “수업 화면이 열려 있지 않아요. 전자칠판 · TV에 보여 주려면 열어요.” + ‘수업 화면 열기’. 팝업이 막혀 못 연 때만 예전처럼 경고 |
| 모바일 리모컨 · 수업 중 | ‘학생 화면’ 칸 | ‘수업 화면’ 칸, 닫혀 있으면 ‘수업 화면 · 열려 있지 않아요’(교사 PC가 알려 주는 상태 `hub.stage`) |

- 수업 도중 수업 화면을 처음 열거나 닫았다 다시 열면, 교사 PC가 지금 상태로 그려서 **지금 장면**부터 보여요(영상은 멈춘 채, 예전 그대로).
- 이미 열린 수업 화면은 시작하면 저절로 첫 장면으로 바뀌어요(PC가 그리는 창이라서).
- 시작 요청 중복 · 늦은 답 · PC 끊김 처리(`sta-` → `go-`, 4초 대기, `db.settle`)는 예전 그대로예요.

## 3. 모바일에서 수업 화면 열기(하지 않는 것)

휴대폰은 다른 기기의 브라우저 창을 열 수 없어요. 휴대폰의 요청으로 교사 PC가 창을 여는 것도 하지 않아요(팝업 차단을 피하거나 PC에 창을 강제로 띄우는 일이라서).
그래서 리모컨은 **상태와 여는 방법**만 보여 줘요. 전자칠판 브라우저가 직접 여는 수업 화면 주소(`#stage`)는 그 기기에서 같은 구글 계정으로 로그인해야 해서(공용 전자칠판에 교사 계정 로그인), 이번에는 리모컨 메뉴에 넣지 않았어요. 필요하면 따로 정해요.

- 기존 시험에서 바뀐 것: 이름이 바뀐 문구, 준비 화면 줄(‘수업 화면 확인 전’ → ‘수업 화면 열기 · 없어도 시작할 수 있어요’), 수업 중 닫힌 수업 화면 안내 문구, 그리고 ‘휴대폰에서 수업 시작’ 시험의 첫 부분(예전: 수업 화면이 없으면 막혀야 함 → 지금: 막히지 않고 상태만 말함). 나머지 기대는 그대로예요.

## 4-1. 이번에 본 기존 시험의 흔들림(이 변경과 무관)

전체 시험 중 `progress.spec.js` ‘장면 수 1 · 3 · 12 · 20 · 50’이 이 PC에 다른 프로젝트의 E2E가 함께 돌던 때 가끔 실패했어요(교사 화면 머리를 다시 그리는 순간에 크기를 재서 `null` · 0이 나옴). 같은 조건에서 24번씩 돌리면 **PR #15 앱 11번 · 이 브랜치 4번** 실패해, 이 변경이 만든 문제가 아니에요. 시험 기준은 그대로 두고, 재는 순간을 기다리게 고치는 일은 따로 해요. 같은 때 실패한 `classroom.spec.js`(긴 장면 이름) · `control.spec.js`(승인 직후 미리보기)는 다시 돌리면 15/15 · 3/3 통과했어요.

## 5. 실기기에서 볼 것
