# 1단계-1 실시간 연결 설계: 휴대폰으로 넘기면 교사 PC와 TV가 함께

> **상태: 구현 · 에뮬레이터 검증 끝, 실제 Firebase 연결 전(2026-11-03).** 브랜치 `feature/stage-1-realtime`(PR #3 `improve/stage-0.7-design` 위, main에 병합됐다고 가정하지 않음).
> 실제 Firebase 프로젝트는 아직 없어요. `public/navi-config.js`가 비어 있어서 배포된 앱은 0.7과 똑같이 이 기기 안에서만 동작해요. 검증 결과는 9번.
> **Firebase로 정했어요(2026-11-02, 교사).** Supabase는 무료로 켤 수 있는 프로젝트 2개가 다른 서비스로 차 있어서 접었어요. Supabase 초안(`supabase/`)은 지우지 않고 ‘보류’로 남겨요.
> Firebase 프로젝트 만들기, 보안 규칙 배포, 구글 로그인 켜기는 아래 6번 순서대로 **하나씩 승인받은 뒤** 해요(아직 하지 않았어요).
> 먼저 읽을 것: `docs/STAGE1-DESIGN.md`(1단계 전체 구조 문제), `CLAUDE.md`(‘window.claude 자리를 그대로 채운다’).

## 0. 한눈에

```
휴대폰(리모컨) ──구글 로그인(같은 계정)──┐
                                          ▼
                       Firebase 전용 프로젝트(무료 Spark, Firestore 서울)
                       teachers/{교사 id}/
                         · sessions/s{PIN}  수업 진행 상태
                         · lessons/deck     지금 수업 내용(글자)
                         · lessons/settings PIN · 화면 설정
                         · peers/{기기}      지금 접속한 기기
                                          ▲
교사 PC(교사 화면) ──구글 로그인──────────┘
   └─ 같은 PC가 연 창 = 학생 화면(TV · 전자칠판, HDMI)
```

- **학생 화면(TV)은 교사 PC가 연 창**이에요(0.7 그대로). ‘휴대폰으로 넘기면 TV가 넘어간다’는 휴대폰 → Firestore → 교사 PC → TV 창 순서로 일어나요. TV는 따로 로그인하지 않아요.
- **Firebase가 잘 맞는 이유**: 시안이 쓰는 `window.claude.use("db")` 모양(`doc` · `onSnapshot` · `set` · `update` · `hasPendingWrites` · `collection().orderBy().limit()` · `add`)이 원래 Firestore 모양이에요.
  누르면 바로 화면에 반영하기, 끊기면 다시 잇기, 다시 이어지면 놓친 변화 채우기를 Firestore가 해 줘서, 직접 만들 것이 줄어요.

| 목표 | 어디서 |
| --- | --- |
| 1. 교사 PC에서 수업 시작 | PC의 `start()`가 세션 문서를 새로 써요(2-3) |
| 2. 휴대폰 QR 연결 · 로그인 | QR `주소#remote-PIN` → 구글 로그인 → 같은 계정이면 바로 연결(2-6) |
| 3. 휴대폰으로 이전 · 다음 | 휴대폰이 세션의 `cur`를 바꿔 써요(2-3) |
| 4. 교사 PC · 학생 화면에 실시간 반영 | PC가 실시간으로 받아 다시 그리면 TV 창도 함께 바뀌어요(2-3) |
| 5. 끊기면 자동 재연결 · 지금 장면 복원 | Firestore가 다시 잇고, 이어지면 서버의 지금 장면으로 맞춰요(2-4) |
| 6. 신호등 동기화 | 신호등은 ‘덧붙이기’(`arrayUnion`)로 보내서 동시에 눌러도 빠지지 않아요(2-3) |

## 2. 설계

### 2-1. 무엇을 계정(Firestore)에 두나

| 자료 | 1단계-1 | 이유 |
| --- | --- | --- |
| 수업 진행 상태 `sessions/s{PIN}` | **계정** | 휴대폰 · PC가 함께 봐야 해요 |
| 지금 수업 내용 `lessons/deck` | **계정**(PC → 휴대폰 한 방향) | 휴대폰이 핵심 발화를 보여 줘야 해요. 올린 파일 수업은 글자만(0.7 `wordsOnly`) |
| 설정 `lessons/settings` | **계정** | PIN이 새로고침에도 그대로여야 휴대폰이 이어져요 |
| 수업 기록 · 최근 수업 · 고친 예시 수업 · 0.7 수업 복구 사본 | **이 브라우저 그대로** | 1단계-2에서 ‘가져올까요?’로 옮겨요. 지금 기록은 하나도 바뀌지 않아요 |

- 앱 코드에서는 `db` 하나로 갈리던 자리를 **`db.scope`**(무엇을 계정에 두는지 목록)로 나눠요. shim은 `["sessions", "lessons"]`를 줘요.
  `scope`가 없으면(아티팩트 런타임) 지금처럼 전부 계정이에요. 1단계-2에서 `"memos"`를 더하면 기록도 계정으로 가요.
- **로그인하지 않았으면 `window.claude`를 아예 넣지 않아요.** 그래서 로그인 전 화면과 동작은 0.7과 한 글자도 같고, 기존 시험 171개가 그대로 지켜 줘요.

### 2-2. 교사 PC가 중심

- **학생 화면은 PC의 창**이라 PC가 중심이에요. 수업 내용과 설정은 PC가 올리고 휴대폰은 받기만 해요.
- **기록은 PC가 저장해요.** 휴대폰에서 ‘수업 끝내기’를 눌러도, PC가 ‘끝남’을 받아 이 브라우저에 저장해요.
  기록 id는 0.7처럼 수업 시작 시각(`local-…`)이라 두 번 저장돼도 1건이에요. 휴대폰 브라우저에는 기록을 만들지 않아요.
- PC는 휴대폰이 바꾼 것도 받을 때마다 0.7 복구 사본(`navi-run`)에 써요. 인터넷이 끊겨도 PC 쪽 복구는 그대로예요.

### 2-3. 동기화 규칙

- 세션은 문서 하나(`teachers/{id}/sessions/s{PIN}`)예요.
  - `update`는 바꾼 칸만 서버에서 합쳐요. 다른 기기가 바꾼 칸을 덮지 않아요.
  - 신호등 · 질문 메모는 **덧붙이기**(`arrayUnion`)로 보내요. 휴대폰과 PC가 같은 순간에 눌러도 둘 다 남아요. 개수 자르기(80 · 40)는 읽을 때 앱이 해요.
  - 누르면 바로 화면에 반영되고, 서버가 받으면 `hasPendingWrites`가 꺼져요(Firestore 기본 동작).
- 받기: `onSnapshot`(메타데이터 변화 포함). 보안 규칙 때문에 내 계정 것만 와요. 한 문서의 소식은 순서대로 와요.
- 같은 칸을 동시에 바꾸면(예: 두 기기가 같은 순간 ‘다음’) 나중 것이 이겨요. 둘 다 ‘다음 장면’이라 결과는 같아요.
- 시계: 기기마다 시계가 달라요. 다른 기기가 장면을 넘긴 소식이 오면 그 `enteredAt`으로 차이를 맞춰요(0.7까지 있던 `clockOff` 그대로).
  쓸 때마다 `at`(그 기기 시각)을 함께 적어서, 교사 PC를 다시 열 때 서버 쪽과 이 브라우저 사본 중 더 최근 것을 골라요.
- **매초 쓰지 않아요.** 화면의 시계는 각 기기가 `t0` · `enteredAt`으로 스스로 계산해요. 쓰기는 장면 이동 · 신호 · 질문 · 자료 · 도구 · 끝내기처럼 상태가 바뀔 때만이에요(9번에서 6초 동안 쓰기 0번 확인).

### 2-4. 끊김과 다시 잇기

- 연결 상태는 **그대로** 보여 줘요. 되는 것처럼 보이게 하지 않아요.
  - 기기 연결됨(서버가 확인한 소식) · 연결하는 중(처음) · 연결 끊김 · 다시 연결하는 중(`fromCache = true`, 또는 브라우저가 `offline`을 알릴 때 바로) · 이 기기만(로그인 안 함).
- 다시 잇기는 Firestore가 해요. 다시 이어지면 서버의 최신 문서를 스스로 보내 줘요(놓친 변화 채우기).
  Firestore는 웹소켓이 아니라 HTTPS 연결(WebChannel, 필요하면 긴 폴링)을 써서, 웹소켓을 막는 학교망에서도 될 가능성이 높아요.
- 휴대폰 화면이 다시 켜질 때(`visibilitychange`), 인터넷이 돌아올 때(`online`)는 연결을 한 번 다시 깨워서 기다림을 줄여요.
- **휴대폰**: 끊긴 동안(`fromCache`)은 넘기기 · 신호 단추를 막고 ‘연결 끊김 · 다시 연결하는 중’을 보여 줘요. 보내지 못할 걸 보낸 척하지 않아요(Firestore는 끊긴 동안 쓰기를 모았다가 나중에 보내므로, 막지 않으면 늦게 넘어가요).
  다시 이어지면 서버의 지금 장면으로 맞춰요. 화면 꺼짐은 지금처럼 화면 켜 두기(Wake Lock)로 줄여요.
- **휴대폰의 조작은 조건부로 보내요(2026-11-03 추가).** Firestore는 보내지 못한 쓰기를 모았다가 다시 이어지면 보내는데, 휴대폰은 ‘보내는 길만 끊긴’ 상태를 바로 알아채지 못해서 오래된 ‘다음’이 몇 초–몇 분 뒤 적용될 수 있었어요(9-8). 그래서 휴대폰 조작은 모아 두지 않는 거래(transaction)로 보내고,
  - 서버의 지금 상태가 휴대폰이 본 상태(`at`)와 같을 때만 적용해요(그 사이 교사 PC가 바꿨으면 버려요). 신호등 · 질문 메모는 덧붙이기라 이 확인 없이 둘 다 남겨요.
  - 누른 뒤 3초 안에만 적용해요(넘으면 버려요). 버리면 휴대폰은 ‘보내지 못했어요. 지금 장면을 보고 다시 눌러 주세요.’를 4초 보여 주고 서버의 지금 장면으로 돌아와요.
  - 누른 차례대로 하나씩 보내서, 빠르게 여러 번 눌러도 누른 만큼 넘어가요.
- **교사 PC**: 끊겨도 수업은 계속돼요(TV는 같은 PC의 창이라 그대로). 바꾼 칸은 Firestore가 모았다가 다시 이어지면 보내요(PC가 기준. 학생 화면이 PC의 창이라 PC가 보여 준 장면이 맞는 장면이에요).

### 2-5. 누가 접속했는지 (이번에는 하지 않았어요)

- Firestore에는 ‘접속 끊김 알림’이 없어서, 휴대폰 몇 대가 붙었는지 알려면 기기마다 30초쯤마다 ‘살아 있음’을 써야 해요.
  교사가 ‘상태가 바뀔 때만 저장’을 정해서 이번에는 넣지 않았어요. 보안 규칙에서도 그 자리(`peers`)를 뺐어요.
- 그래서 교사 화면의 ‘기기 연결됨’은 **이 기기가 서버와 이어졌다**는 뜻이고, 휴대폰이 실제로 몇 대 붙었는지는 보여 주지 않아요. 휴대폰은 QR로 들어오면 지금 장면이 바로 보여서 연결을 눈으로 확인할 수 있어요.
- 필요하면 1단계-2 뒤에 Realtime Database의 접속 끊김 알림(onDisconnect)으로 쓰기 없이 할 수 있는지 따로 봐요.

### 2-6. 로그인과 QR

- 로그인하지 않으면 지금처럼 이 기기 안에서만 동작해요. 0.7의 모든 기능이 그대로예요.
- 교사 PC: 발표 설정의 ‘휴대폰 리모컨’ 칸에 **구글로 로그인** 단추. 로그인한 계정 이메일과 로그아웃을 같은 칸에 보여 줘요.
- 로그인 방식은 **팝업**(`signInWithPopup`)이에요. 요즘 크롬 · 사파리는 다른 사이트 저장소를 막아서, 팝업 대신 쓰는 ‘다시 돌아오기’ 방식이 Vercel 주소에서는 깨져요(Firebase 공식 안내).
  휴대폰에서 팝업이 막히면 B안: Vercel이 `/__/auth/`를 Firebase로 넘겨 주게(rewrite) 하고 ‘다시 돌아오기’ 방식을 써요.
- 휴대폰: QR을 찍으면 `주소#remote-PIN`이 열려요 → ‘교사 PC와 같은 구글 계정으로 로그인’ → 로그인 뒤 바로 연결돼요.
  - 다른 계정이면 그 계정 이메일을 보여 주고 ‘교사 PC와 다른 계정이에요’라고 말해요(보안 규칙 때문에 남의 수업은 아예 보이지 않아요).
- PIN 4자리는 비밀번호가 아니라 ‘어느 수업인지’ 고르는 표시예요(`STAGE1-DESIGN.md` 3번). 보안은 계정(보안 규칙)이 맡아요.
- Firebase JS SDK는 `12.19.0`(2026-09-09)으로 고정해요. 빌드 단계가 없어서 shim은 `public/claude-shim.js`에 두고, SDK는 공식 CDN(`www.gstatic.com/firebasejs/12.19.0/`)에서 로그인한 뒤에만 불러요.

### 2-7. PC 새로고침 · 창 닫힘 (0.7 수업 복구와 함께)

## 3. 데이터와 보안 규칙 (초안, 배포 전)

| 경로 | 내용 | 규칙 |
| --- | --- | --- |
| `teachers/{id}/lessons/deck` | 지금 수업 내용(글자) | 자기 것만, 앱이 쓰는 칸 14개만(`v · kind · title · pages · res`는 꼭), 종류는 example · pdf · pptx, 제목 200자, 장면 100 · 자료 400개까지, 지우기 없음 |
| `teachers/{id}/lessons/settings` | PIN과 화면 설정 | 자기 것만, 발표 설정 칸 18개만, PIN 숫자 4자리, 반 이름 40자, 인원 1–40, 켜고 끄는 칸은 참 · 거짓만, 지우기 없음 |
| `teachers/{id}/sessions/s{PIN}` | 수업 진행 상태(장면 · 시간 · 신호등 · 질문 메모 · 띄운 자료) | 자기 것만, 칸 이름 목록 고정, 배열 크기 상한, 지우기 없음 |
| 그 밖 | | 모두 거절 |

- 파일: `firestore.rules`. 학생 정보 · 비밀 키는 없어요. 허용 · 거부는 `tests/rules.spec.js`가 에뮬레이터로 봐요.
- **구글 로그인만 받아요**: 같은 UID라도 익명 · 이메일 · 전화 로그인이면 자기 자리조차 거절(`sign_in_provider == 'google.com'`). 나중에 다른 로그인 방법이 켜져도 아무 계정이나 데이터를 만들 수 없어요.
- **접근 기준은 로그인한 교사의 UID 하나예요**: 모든 경로가 `teachers/{uid}/…`이고 `request.auth.uid == uid`일 때만 열려요. PIN · 세션 이름(`s1234`) · 교사 id를 알아도 그 교사로 로그인하지 않으면 읽기 · 쓰기 · 모든 교사 한꺼번에 찾기(collection group)가 모두 거절돼요(다른 교사, 로그인 안 한 사람, 익명 로그인 모두 시험). 같은 PIN을 쓰는 다른 교사의 수업은 그 교사 자리에 따로 있어요.
- **배열 안의 배열**: 예시 수업의 표(`rows`) · 낱말(`defs`) · 자료 카드(`card.rows`)는 배열 안에 배열이 있어요. Firestore는 이걸 그대로 못 담아서(처음 시험에서 ‘수업 시작’이 멈췄어요) shim이 저장할 때 안쪽 배열을 `{ __a: [...] }`로 감싸고 읽을 때 풀어요. 앱이 보는 모양은 그대로예요(`tests/roundtrip.spec.js`).
- Firestore 위치는 **서울(asia-northeast3)**. 한 번 정하면 바꿀 수 없어요.
- Supabase 초안 `supabase/migrations/0001_init.sql` · `0002_stage1_1_realtime.sql`은 지우지 않고 맨 위에 ‘보류’를 적었어요.
