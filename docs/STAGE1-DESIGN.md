# 1단계 전에 정할 설계

> **2026-11-02: 1단계는 Firebase로 정했어요**(`docs/STAGE1-1-REALTIME.md`). 아래 문제와 제안은 그대로 유효하고, 이름만 바꿔 읽어요: `navi_sessions` → `teachers/{id}/sessions/s{PIN}`, `navi_docs` → `teachers/{id}/lessons/…`, RLS → Firestore 보안 규칙(`firestore.rules`), Storage 서명 주소 → 1단계-2에서 파일 저장소를 정할 때 다시 봐요.

0.5단계에서는 DB와 서버를 건드리지 않았어요. 아래는 `src/claude-shim.js`로 `window.claude`를 채울 때 부딪힐 구조 문제와 제안이에요.
**적용은 교사 확인 뒤에 해요.** 특히 지우기, RLS 넓히기, 대량 수정은 먼저 물어봐요.

## 1. 여러 수업 저장

- **지금**: 교사마다 `lessons/deck` 문서가 하나뿐이에요. 새 PDF를 올리면 앞 수업을 덮어써요. 같은 수업인지는 `deck.key`로 알아봐요(`memos.key`와 짝).
- **문제**: 3반을 같은 차시로 연달아 가르치는 건 괜찮아요. 하지만 과목이 다른 수업을 미리 여러 개 준비해 둘 수 없어요.
- **제안**
  - `navi_lessons (id uuid, owner, key, title, kind, data jsonb, updated_at)` 표를 만들고, `lessons/settings`에 `currentLesson`(id)을 둬요.
  - shim은 `db.doc("lessons/deck")`을 "지금 고른 수업 행"으로 이어 줘요. 그러면 화면 코드는 그대로예요. 수업 목록 화면은 그다음에 만들어요.
  - 크기는 40장 × (글자 600 + 노트 400자)에 자료 120개를 더해도 수십 KB라 jsonb 하나로 충분해요. 그림은 Storage 경로만 넣어요.
  - 교탁 탭 두 개에서 동시에 고치면 나중에 쓴 쪽이 이겨요. `updated_at`을 비교해서 "다른 창에서 바뀌었어요" 정도만 알려 줘요.

## 2. 세션(수업 진행 상태) 구분

- **지금**: `sessions/s{PIN}` → `navi_sessions (owner, pin)`. PIN을 바꿀 때마다 행이 새로 생기고, 끝난 수업 상태도 그대로 남아요.
- **문제**
  - 끝난 세션 행이 계속 쌓여요.
  - Realtime `postgres_changes` 필터는 칼럼 하나만 비교할 수 있어서 `(owner, pin)`으로 바로 거르기 어려워요.
  - 같은 PIN으로 다음 반 수업을 시작하면 앞 반 상태를 덮어써요. `fresh()`로 새로 쓰니 동작은 맞지만, 기록은 `memos`에만 남아요.
- **제안**
  - `navi_sessions`에 `id uuid`를 더하고, 구독은 `id=eq.…` 하나로 걸러요(권한은 RLS가 owner로 막아요). settings에는 PIN과 지금 세션 id를 함께 둬요.
  - 끝난 지 7일이 지난 세션은 수업 시작 때나 예약 작업으로 정리해요(삭제라서 적용 전에 확인받아요).
  - 상태 jsonb는 `log` 80개, `reactions` 40개로 이미 잘려 있어서 Realtime으로 보내기에 충분히 작아요.

## 3. PIN 보안

- PIN 4자리는 **비밀번호가 아니라 "어느 수업인지" 고르는 표시**예요. 경우의 수가 1만 개라 쉽게 맞힐 수 있어요.
- 1단계(휴대폰도 같은 계정으로 로그인)에서는 RLS(`owner = auth.uid()`)가 막아 줘서, PIN이 새도 남의 수업은 볼 수 없어요. 이 방식을 유지해요.
- 3단계(로그인 없이 QR만으로 휴대폰 참여)를 하려면 PIN만으로는 안 돼요.
  - 수업마다 긴 임시 토큰(128비트 이상)을 만들어 QR에 넣어요. 화면에는 계속 PIN만 보여요.
  - 토큰은 서버 함수에서 확인하고, 수업이 끝나면 10분쯤 뒤 만료해요. 틀린 시도 횟수도 제한해요.
  - `service_role` 키는 서버 환경 변수에만 둬요.

## 4. 비공개 Storage 파일 주소

- **지금**: `assets.upload(blob) → { id, url }`. 화면은 `url`을 덱에 그대로 저장해요(`pages[].url`, `res[].link`). `id`도 `aid`로 함께 저장해요.
- **문제**
  - 비공개 버킷의 서명된 주소(signed URL)는 만료돼요. 다음 날 열면 그림이 깨져요.
  - 공개 버킷은 주소만 알면 누구나 열 수 있어요. 비바샘·교과서 자료라 저작권 문제가 생겨요.
- **제안**
  - 버킷은 비공개로 둬요. 덱에서 믿을 값은 `aid`(저장 경로 `owner/…`)예요.
  - shim이 `lessons/deck`을 읽을 때 `aid`가 있는 항목의 `url`·`link`를 `createSignedUrls`로 한꺼번에 새로 채워 화면에 넘겨요. 저장할 때는 서명된 주소를 빼요.
  - 만료 시간은 넉넉히(예: 6시간) 잡아요. 화면이 오래 켜져 있으면 만료 전에 다시 서명해서 `onSnapshot`으로 바꿔 줘요.
  - 슬라이드 창(같은 페이지가 연 팝업)과 TV의 그림·PDF 표시도 같은 서명 주소를 그대로 써요.
  - 버킷에 `file_size_limit`(예: 20MB)와 `allowed_mime_types`(`image/*`, `application/pdf`)를 정해요.
  - 새 PDF를 올리면 앞 장 그림이 남아요(고아 파일). 교체할 때 `assets.delete`로 지우거나 정리 작업을 둬요(지우기라서 확인 뒤에).

## 5. `supabase/migrations/0001_init.sql` 초안을 볼 때 확인할 것

- `updated_at`에 기본값만 있고, 고칠 때 바뀌게 하는 트리거가 없어요.
- `navi_memos`의 `deck_key`, `at` 칼럼과 `data` 안의 값이 겹쳐요. shim에서 함께 채워야 해요.
- Realtime 대상이 `navi_sessions`뿐이에요. 휴대폰 프롬프터는 덱(장면 발화)도 읽어야 해서, 덱도 실시간으로 받을지, 수업 시작 때 한 번 읽을지 정해야 해요.
- Storage 정책은 폴더 = 교사 id라서 맞아요. 크기·형식 제한만 더하면 돼요.
- 학생 정보는 들어가지 않아요. `memos`에는 반 이름(`cls`)과 인원 수 설정만 있어요.

## 6. 0.5단계에서 더한 데이터 (지우거나 바꾼 것 없이 추가만)

| 위치 | 필드 | 뜻 |
| --- | --- | --- |
| `lessons/deck` | `prep` | `"ai"` AI가 정리 / `"basic"` 기본 정리(AI 아님) |
| `pages[]` | `ar` | PDF 장의 가로÷세로 비율. TV에서 그 비율로 그려요 |
| `res[]` | `mt` | 파일 자료의 종류 `"image"` · `"pdf"`. TV에 무엇을 띄울지 정해요 |
| `memos` | `local-…` id | 저장소가 없을 때 이 창 안에만 있는 기록. Supabase에서는 쓰지 않아요 |

## 7. 0.6단계에서 생긴 것을 옮길 때

- **이 브라우저 저장(IndexedDB `navi-local`)**: `records`(수업 기록, `local-…` id)와 `lessons`(최근 수업, 고친 예시 수업의 글자)는 `local` 객체 하나로만 읽고 써요. shim이 생기면 이 층은 로그인 전에만 쓰고, 로그인 뒤에는 “이 브라우저의 기록 n건을 계정으로 옮길까요?”라고 물어 `navi_memos`에 옮겨요(옮긴 뒤 지울지도 물어요).
- **여러 수업**: 지금은 예시 수업을 `lessonId`로 골라 열고, 고친 내용을 `lessons` 저장소에 둬요. 1번 제안의 `navi_lessons` 표가 이 자리를 이어받아요(키 = `lessonId` 또는 파일 수업의 id).
- **신호등**: 세션 문서의 `reactions[]`에 `red | yellow | green | clear` 이벤트가 시간순으로 쌓여요(최대 80개). 장면의 지금 판단은 마지막 이벤트예요. 기록 v2에는 장면별 결과(`scenes[].sig`), 개수(`sig`), 전체 순서(`events`)를 남겨요.
- **질문 메모**: 세션 문서의 `qs[]`(최대 40개), 기록의 `questions[]`. 학생 이름을 적지 않도록 화면에서 안내하지만, 서버에서 막을 방법은 없어요. 1단계에서도 길이 제한(120자)만 두고 내용은 교사 책임으로 남겨요.
- **예시 기록**: `lessons.js`의 예시 기록 3건은 DB에 넣지 않아요. 화면에서만 ‘예시 기록’으로 보여 줘요.
