# 수업 시계 · 끊긴 뒤 동기화 (2026-11-23, PR #27)

PC와 휴대폰의 수업 시간이 서로 다르게 보이고, 끊긴 동안 다른 기기가 넘긴 뒤 기록 시간이 어긋나던 문제를 고쳤어요. 설계는 합의한 B + R2 그대로예요(아티팩트 ‘수업 시계 설계’). 예전 조사는 `docs/CLOCK-RECONNECT.md`.

## 1. 원인

- **모든 기기가 늦게 온 소식으로 시계를 맞췄어요.** 다른 기기가 넘긴 소식을 받으면 `clockOff = Date.now() − enteredAt`으로 자기 시계를 맞췄어요. 소식이 넘긴 그 순간에 온다고 보는 방식이라, 끊긴 동안 넘긴 소식이 늦게 오면 늦은 만큼 시계가 늦어졌어요. **수업을 맡은 PC도** 그렇게 맞춰서, PC가 늦어지면 기록도 짧아졌어요.
- **끊긴 PC의 오래된 쓰기가 휴대폰 진행을 덮었어요.** PC가 끊긴 동안 옛 장면에서 넘기면, 이어진 뒤 그 쓰기가 휴대폰이 넘긴 장면 위에 그대로 적혔어요.
- **장면 시간을 정수 초로 적었어요.** 장면마다 반올림해서 짧은 장면은 0초로 사라지고, 합이 실제 시간과 달랐어요.
- **시스템 시계가 바뀌면** 수업 시계가 거꾸로 가거나 튀고, 장면 시간이 음수가 됐어요.

## 2. 바꾼 것

### 2-1. 기준 시계(B)

- 수업을 맡은 PC 창(`lessons/hub.pc`)이 수업 시계예요. **이 창은 다른 기기를 보고 시계를 바꾸지 않아요.**
- 따라가는 기기(휴대폰 · PIN 휴대폰 · 따로 연 수업 화면 · 수업을 맡지 않은 PC)는 맡은 창이 **방금 쓴** 세션 쓰기로만 시계를 맞춰요. 표본이 되려면 모두 맞아야 해요.
  - `by.at = at`, `by.pc = hub.pc`(예전 앱이나 다른 창의 쓰기가 아님)
  - 같은 수업(`t0`), 같은 run(둘 다 있을 때)
  - 서버가 확인한 값(`fromCache` · `hasPendingWrites` 아님)
  - 끊겼다 이어진 뒤 · 페이지를 연 뒤 · 화면이 다시 보인 뒤 · 인터넷이 돌아온 뒤의 **첫 값이 아님**
  - 차이가 2분 안
- 표본 하나 = `Date.now() − at` = 시계 차이 + 오는 데 걸린 시간. **최근 5분 표본 중 가장 작은 값**을 써요(가장 빨리 온 것).
- 수업 전 대기 화면의 휴대폰은 ping/pong도 표본으로 써요: `(보낸 때 + 받은 때) / 2 − pong.at`.
- 맡은 창이 바뀌면(`hub.pc`) 따라가는 기기는 표본을 비우고(시계는 다음 표본까지 그대로), 수업을 넘겨받은 PC는 따라가던 시계를 그대로 써요. 그 수업의 시계는 `navi-run`에 함께 남아 새로고침 뒤에도 같아요. 새 수업은 맡은 창 자기 시계로 시작해요.
- 맡은 창은 쓰기마다 `by: { pc, at }`를 붙여요. **늦게 보내는 쓰기(누른 뒤 2초 넘게 기다린 것)는 `by: null`** 이라 표본이 되지 않아요(끊긴 동안 쌓였다 이어진 뒤 간 쓰기가 휴대폰 시계를 늦추지 않게). 서버에서 받은 `by`는 다시 보내지 않아요.

### 2-2. 시계가 바뀌었을 때

1초마다(그리고 화면이 다시 보일 때 · 인터넷이 돌아올 때) `Date.now()`의 변화와 단조 시계(`performance.now()`)의 변화를 비교해요.

- **1.5초 넘게 거꾸로**: 수업 시계가 그대로 이어지게 `clockOff`를 그만큼 옮겨요(모든 기기). 따라가는 기기는 표본도 비워요.
- **1.5초 넘게 앞으로**, 맡은 창: 사이트의 `Date`(HEAD 요청)로 확인해요. 수업 시작 때 잰 차이(`d0`)와 지금 차이(`d`)를 비교해서
  - `|d − d0| ≤ 2초` → 실제로 시간이 흘렀어요(절전). 그대로 둬요.
  - `|(d − d0) + 점프| ≤ 2초` → 시계를 바꿨어요. 점프만큼 되돌려요.
  - 둘 다 아니거나 답이 없으면 고치지 않고 교사 화면에 ‘시계를 확인하지 못했어요. 수업 시간이 조금 다를 수 있어요.’
- 앞으로 점프, 따라가는 기기: 시계는 그대로 두고 표본만 비워요(다음 표본에서 맞춰요).
- 음수 장면 시간은 숨기지 않아요(0으로 바꾸지 않음).

### 2-3. 기록 0.1초(R2)

- 세션 `log[].sec`은 밀리초까지(소수 셋째 자리).
- 기록 전체 = 장면 시간(밀리초) 합을 **한 번만** 0.1초로 반올림.
- 장면은 0.1초로 내림하고, 남은 것은 나머지가 큰 장면부터 0.1초씩 더해 **장면 합 = 전체**(0.1초 단위로 정확히).
- 계정 기록(`recV3`)도 0.1초를 그대로 둬요. 화면은 예전처럼 분:초.

### 2-4. 끊긴 동안 쌓인 PC 쓰기

PC 쓰기는 예전처럼 거래(`db.held`)로 가고, 거래 안에서 서버의 지금 수업과 맞춰 봐요(`ownMerge`, 순수 함수). 쓰기마다 그 쓰기 직전 PC 화면의 수업(`prev`)을 함께 둬요. 장면 열쇠 = (장면, 들어간 시각, 기록 길이).

| 쓰기 | 규칙 |
| --- | --- |
| 장면 넘기기(cur · enteredAt · log · vid) | 서버 장면 열쇠 = `prev`의 열쇠일 때만. 아니면 적지 않고 교사 화면에 ‘연결이 끊긴 동안 휴대폰이 넘겨서 이 PC에서 넘긴 것은 반영하지 않았어요’ + [그 장면으로 가기] |
| tv · blank · tool · vid | 장면 열쇠가 같고, 서버 값이 `prev` 값과 같을 때만(그 사이 아무도 바꾸지 않음). 띄우려던 자료 · 가림 · 도구가 적히지 않았으면 ‘연결이 끊긴 동안 수업이 바뀌어서 이 PC에서 띄운 것은 반영하지 않았어요’ + [다시 띄우기](지금 장면에, 타이머는 처음부터) |
| 신호등 · 질문 메모 | 늘 덧붙여요 |
| 쓴 자료(used) | 합쳐요 |
| 끝내기 | 서버가 이미 끝났으면 그대로. 장면 열쇠가 같으면 적어요. 아니면 적지 않고 ‘끝내기 뒤에도 휴대폰에서 수업이 이어졌어요. 끝내려면 다시 눌러 주세요’ |
| at · by | 무엇이든 적었을 때만: `at = max(쓰기의 at, 서버 at + 1)`, `by.at = at` |
| 다른 수업(t0가 다름) | 적지 않아요(알림 없음) |

- 적지 않은 쓰기는 PC 화면에 남기지 않고, 서버의 수업을 그대로 보여 줘요(`ownRedo`).
- 알림은 `navi-run`에 남아 새로고침 뒤에도 보여요(‘끝나지 않은 수업’ 줄에도 ‘연결이 끊긴 동안 반영하지 않은 조작이 있어요’). 닫거나 수업이 끝나면 사라져요. 넘기기 · 끝내기 알림이 띄우기 알림보다 먼저예요.
- **예전 동작과 다른 점(2026-11-21 교사 결정)**: 예전에는 끊긴 PC가 보내지 못한 넘기기가 이어진 뒤 그대로 적혀, 휴대폰이 넘긴 진행 위로 ‘교사 PC 기준’으로 모였어요. 이제는 서버의 더 새 진행을 덮지 않고, 교사가 [그 장면으로 가기]로 고를 수 있어요. 그래서 `tests/realtime.spec.js` ‘끊긴 동안 양쪽에서 바꾸기’의 기대를 결정에 맞게 바꿨어요(세 화면이 같아지는 검사는 그대로 + 알림 · [그 장면으로 가기]로 TV 장면에 모이는 것까지 더 봐요).

### 2-5. 기록 다시 저장

수업이 끝나 서버가 확인한 마지막 세션이 이 PC가 만든 기록과 다르면(끊긴 동안 휴대폰이 누른 신호 · 질문이 끝낸 뒤에 서버에 닿음), **같은 id**(`local-{t0}` · 계정 `r-{t0}`)로 한 번 다시 저장해요. 끝 시각 = 마지막 장면에 들어간 시각 + 그 장면 시간. 교사가 이미 고친 기록(`editedAt`)은 덮지 않아요. 기록이 두 건 생기지 않아요.

## 3. 잰 값(에뮬레이터, `tests/clock.spec.js`)

- 모든 경우 수정 후 장면 합 = 전체(0.1초), 음수 장면 없음, 기록은 수업마다 한 건이에요.
- 수정 전: 16개 중 **11개 실패**(1 · 2 · 3 · 5 · 8 · 9 · 11 · 12 · 13 · 14 · 16. 16은 나중에 더한 시험이라 수정 전 코드(f6e9908)에서 따로 잼). 수정 후: **17개 모두 통과**(+ 규칙 시험 29개). 17은 [다시 띄우기]를 더하면서 만든 시험이라 수정 전 값은 재지 않았어요.
- 가장 큰 오차: 화면 −20초 → +1초, 기록 −20초 → +0.1초(5번). 정상 연결의 기록 오차 +1.9초 → +0.1초(1번).

## 4. 기존 기록 · 앱과의 호환

- 예전 기록(정수 초)은 그대로 읽고 고치지 않아요. 새 기록만 0.1초예요. 계정 기록 규칙(`records`)은 `totalSec is number`라 그대로 받아요(규칙 바꾸지 않음). 장면 목록 안쪽은 규칙이 보지 않아요.
- 세션 `log[].sec`이 소수가 돼도 예전 앱은 분:초로 반올림해 보여요.
- `by`가 없는 세션(예전 앱이 쓴 것)도 그대로 돼요. 따라가는 기기는 그 쓰기로 시계를 맞추지 않을 뿐이에요.

## 5. Firebase 규칙(에뮬레이터만 바꿈 · 운영 배포 안 함)

`firestore.rules`의 `validSession`에 `'by'`를 더하고 모양만 봐요.

```
function validBy(d) {
  return !('by' in d) || d.by == null
    || (d.by is map && d.by.keys().hasOnly(['pc', 'at']) && d.by.keys().hasAll(['pc', 'at'])
      && d.by.pc is string && d.by.pc.size() <= 64 && d.by.at is number);
}
```

| 검토 | 결과 |
| --- | --- |
| 하위 호환 | `by`는 선택 칸이에요. `by`가 없는 문서 · `null`은 예전처럼 통과해요. |
| 기존 · 신규 앱 혼용 | 새 규칙 + 예전 앱: 예전 앱은 `by`를 쓰지 않고, 서버에서 받은 `by`를 다시 실어도(같은 모양) 통과해요. 그 `by`는 `by.at ≠ at`이라 표본이 아니에요(시계 14). 새 앱 + 지금 운영 규칙: `by` 쓰기가 거절되면 그 수업은 `by` 없이 다시 보내요(`byOff`, 시계 15). |
| 이전 클라이언트 쓰기 차단 | 막지 않아요(칸을 더하기만 함). |
| 인증되지 않은 기기의 시간 조작 | 세션은 `teachers/{UID}/` 아래라 그 구글 계정만 써요. PIN 휴대폰은 세션을 쓰지 못하고 명령만 남겨요(PC가 8초 안의 명령만 받음). 같은 계정의 다른 창이 쓴 `by`는 `by.pc ≠ hub.pc`라 표본이 아니에요. 표본은 2분 안 · 최근 5분 최솟값만 써서 한 번 튀는 값이 시계를 끌고 가지 못해요. |

## 8. 실기기 확인이 필요한 것(미검증)

자동화로는 실제 절전 · 실제 Wi-Fi를 만들 수 없어요. 아래가 끝나기 전까지 **절전 · 실제 끊김의 정확도는 미검증**이에요.

1. **Windows 절전**(교사 노트북): 수업 시작 → 휴대폰 스톱워치 시작 → 2분 뒤 노트북 덮개 닫기(절전) → 휴대폰으로 장면 2번 넘기기 → 3분 뒤 열기 → PC · 휴대폰의 수업 시간과 스톱워치 비교(±1초), ‘시계를 확인하지 못했어요’가 뜨는지 → 끝내고 기록 전체와 스톱워치 비교(±1.5초).
2. **실제 10분 수업**: PC는 학교 Wi-Fi, 휴대폰은 데이터. 중간에 PC Wi-Fi를 30초 끄고 휴대폰으로 넘기기, 휴대폰을 비행기 모드 30초 하고 PC로 넘기기 → 각 화면 시간 · 기록을 스톱워치와 비교.
3. **휴대폰 화면 꺼짐 · 다른 앱으로 갔다 오기**(2분): 돌아온 뒤 수업 시간 ±1초.
4. **Windows 시계 바꾸기**(설정 → 시간 자동 설정 끄고 1분 바꾸기): 수업 시계가 튀지 않는지.

## 9. 알려진 한계

- PC가 끊긴 채 ‘수업 끝내기’를 눌렀는데 그 사이 휴대폰이 넘겼다면, 끝내기는 적지 않고 알림을 보여요. 다만 그 PC는 끝낼 때 휴대폰 연결을 이미 정리해서(PIN 휴대폰 해제 · 새 run), 그 수업의 휴대폰은 다시 연결해야 하고 같은 계정 휴대폰은 그 수업 동안 시계 표본이 없어요. 다시 끝내면 기록은 같은 id로 덮어써요.
- 사이트 `Date`는 1초 단위라 앞으로 점프 확인은 2초 여유를 둬요.
- 새 앱 + 지금 운영 규칙(규칙 배포 전)에서는 휴대폰이 수업 중 표본을 받지 못해요(6절).
- 설계 6절의 ‘표본 없이 다른 PC가 이어받으면 HTTP Date로 두 PC 차이를 알림’은 넣지 않았어요. 앞 PC가 수업 시작 때 잰 기준값이 서버에 없어서, 알리려면 세션에 칸을 더 둬야 해요(규칙 변경). 이어받은 PC가 그 전에 따라가며 표본을 받았다면 시계는 그대로 이어져요.
- ‘허브가 사용 중으로 남는 문제’(로그아웃 · 갑자기 닫은 뒤 다음 창이 ‘이 기기에서 이어서 준비하기’를 눌러야 함)는 이 PR과 별개예요(후속 작업).
