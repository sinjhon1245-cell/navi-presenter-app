## 0단계 — 내 주소로 배포

**지시문**

```
CLAUDE.md와 docs/SPEC.md를 먼저 읽어 줘.
prototype/navi-presenter.html을 그대로 살려서 정적 웹앱으로 만들어 줘.
- public/index.html 로 옮기고, 아티팩트용 첫 줄들(<title>, meta)을 정상적인 HTML 문서(<!doctype html>, <head>, <body>)로 감싸 줘.
- 코드 안의 PAGE_URL을 배포 주소 기준(location.origin + location.pathname)으로 바꿔 줘.
- window.claude가 없을 때도 지금처럼 이 기기 안에서만 동작해야 해.
- Vercel 정적 배포 설정(vercel.json)을 추가하고, 배포 방법을 쉬운 말로 알려 줘.
- Playwright로 1536×864, 390×844에서 준비 화면 → 미리 넘겨 보기 → 끝내기까지 오류 없이 되는지 확인해 줘.
```

**확인**
- 내 주소에서 준비 화면이 열린다
- 미리 넘겨 보기로 끝까지 넘어간다
- ‘슬라이드 창 열기’로 새 창이 뜨고, 교탁에서 넘기면 함께 넘어간다

### 1단계-1 (먼저) — 휴대폰으로 슬라이드 넘기기: 로그인과 실시간 세션

> 기술 설계 · 코드 분석 · 승인받을 외부 변경: `docs/STAGE1-1-REALTIME.md`. 보안 규칙 초안: `firestore.rules`(아직 배포 안 함).
> **2026-11-03 상태**: 구현과 에뮬레이터 검증 끝(Firebase 묶음 19개 3회 반복 모두 통과, 전체 회귀 190 통과 · 실패 0). 실제 Firebase 프로젝트는 아직 없어요. 다음은 설계 문서 6번 순서대로 프로젝트 만들기(교사 승인 · 콘솔).

**목표** (교사가 정한 순서)
1. 교사 PC에서 수업 시작
2. 휴대폰에서 QR로 연결
3. 휴대폰으로 슬라이드를 넘김
4. 교사 화면과 학생 화면이 함께 바뀜
5. 연결이 끊겼다가 다시 이어져도 지금 장면 유지
6. 신호등 기록과 수업 진행 상태 동기화

**정한 것**
- 이 앱만 쓰는 **Firebase 전용 프로젝트**(무료 Spark, Firestore 서울)를 써요. 프로젝트 만들기, Firestore · 로그인 켜기, 보안 규칙 배포는 **실행 전에 교사 승인**을 받아요.
- 휴대폰도 같은 교사 계정(구글)으로 로그인해요. PIN은 비밀번호가 아니라 어느 수업인지 고르는 표시예요(`docs/STAGE1-DESIGN.md` 3번).
- 0.7의 수업 복구(localStorage `navi-run`)는 그대로 두고, 세션 문서가 공유 저장 역할을 이어받아요. 연결이 끊긴 동안에도 교사 PC는 이 브라우저 저장으로 버텨요.

**지시문**

```
1단계-1을 해 줘. CLAUDE.md의 'window.claude 자리를 그대로 채운다'를 따라.
1. docs/STAGE1-1-REALTIME.md를 따라, Firebase 에뮬레이터(demo-navi)로 먼저 만들고 시험해 줘.
2. public/claude-shim.js를 만들어서 claude.use("db")의 sessions/s{PIN}, lessons/deck, lessons/settings를 Firestore로 구현해 줘
   (teachers/{id}/ 아래, onSnapshot, set, update, 신호등은 덧붙이기). 기록·최근 수업·0.7 복구는 지금처럼 이 브라우저에.
3. 보안 규칙(firestore.rules) 배포와 실제 프로젝트 연결은 내가 확인한 다음에 해 줘.
4. 구글 로그인 화면을 추가해 줘. 로그인 전에는 지금처럼 이 기기 안에서만 동작.
5. 두 브라우저(교탁, 휴대폰 크기)로 같은 PIN에서 넘기기·신호·TV 띄우기가 동기화되는지 Playwright로 확인하고,
   tests/classroom.spec.js의 fixme 시험을 실제 시험으로 바꿔 줘. 실제 휴대폰으로도 확인할 순서를 알려 줘.
```

**확인**
- 교탁 PC와 휴대폰을 같은 계정으로 열면, 휴대폰에서 넘길 때 교사 화면과 TV도 넘어간다(반대도)
- 휴대폰의 신호등이 교사 화면 기록에 남는다
- 연결이 끊기면 화면이 ‘연결 끊김’을 그대로 말하고, 다시 이어지면 지금 장면으로 맞춰진다
- 다른 계정으로는 내 수업 세션이 보이지 않는다

### 1단계-2 (그다음) — 수업·설정·기록·파일 저장 옮기기

**지시문**

```
1단계-2를 해 줘.
1. claude.use("db")의 나머지 경로를 Firestore로 옮겨 줘.
   - 여러 수업: teachers/{id}/lessons 아래 수업마다 문서
   - memos → teachers/{id}/memos
2. claude.use("assets")를 파일 저장소로 구현해 줘(Firebase Storage는 Blaze 플랜이 필요해서 먼저 정해요). <img src>에 쓸 수 있는 주소를 돌려줘.
3. 이 브라우저의 기록(IndexedDB navi-local)을 로그인 뒤 계정으로 가져올지 묻고 가져와 줘.
```

- 다른 계정으로는 내 수업이 보이지 않는다

> 휴대폰이 QR만으로 로그인 없이 들어오게 하려면, 수업마다 임시 토큰을 만들어 검사하는 서버 함수가 필요해요. 처음에는 ‘휴대폰도 같은 계정으로 로그인’으로 시작하고, 필요하면 3단계에서 바꿔요.

## 2단계 — AI 서버 함수

**지시문**

```
2단계를 해 줘.
1. api/ai.js (Vercel 서버 함수)를 만들어 줘.
   - 요청: { prompt, modelTier, images?(base64 JPEG 배열) } + Firebase 로그인 토큰(ID 토큰)
   - 토큰을 검증하고, 사용자당 짧은 시간 요청 수 제한을 둬
   - modelTier "quick" → claude-haiku-5-5, "default" → claude-sonnet-5-5
   - 답에서 JSON만 꺼내 돌려주고, 실패는 { code } 로 (rate_limited, upstream_error 등)
   - ANTHROPIC_API_KEY는 Vercel 환경 변수에서만 읽어
2. src/claude-shim.js에 claude.use("sample")을 추가해서 sample.json / sample.limits 가 이 함수를 부르게 해 줘.
   signal(AbortController)도 지원해 줘.
3. 내 PDF를 올렸을 때 분석 결과(장면 이름, 단계, 핵심 개념, 핵심 발화, 추천)가 채워지는지 확인하고,
   한 번 분석에 든 토큰 수를 알려 줘.
```

**확인**
- PDF·PPTX를 올리면 30초~1분 안에 장면마다 핵심 개념과 핵심 발화가 채워진다
- 추천 자료는 내 목록에 있는 것만 나온다
- 브라우저 개발자 도구 어디에도 API 키가 보이지 않는다

## 4단계 — 비바샘 연동 (비상교육 협력 후)

비상교육의 차시 목록·자료 링크 API를 받으면, ‘비바샘 차시 불러오기’를 예시가 아닌 실제 데이터로 바꿔요. 파일은 복사하지 않고 목록과 링크만 가져와요.
