# 학생 화면 안정성: 영상 다시 시작 · 미리보기 노출 · 한 화면 끝내기

2026-11-09 · 브랜치 `fix/stage-screen`(`main` `ac2a6e6`에서) · 고친 파일 `public/index.html` 한 곳.
Firestore 보안 규칙 · Firebase 설정 · 데이터 구조 · 기록 형식은 바꾸지 않았어요. 교사 화면 · 휴대폰 화면 모양도 그대로예요.

## 1. 학생 화면 영상이 처음부터 다시 시작돼요

**원인(재현으로 확인)**
`render()`는 끝날 때마다 `renderStageWin()`을 불러 학생 창을 `root.innerHTML = viewStage(true)`로 통째로 새로 썼어요.
그때 영상 칸(`<iframe>`)도 새로 만들어져 영상이 처음부터 다시 불려요. 학생 화면에 보이는 내용이 하나도 바뀌지 않아도 그랬어요.
한 화면 모드 PC(`role === "stage"`)와 학생 화면 전용 기기(`#stage`)도 `app.innerHTML = viewStage()`로 같은 일이 있었어요. PDF 자료도 같은 이유로 처음 쪽으로 돌아갔어요.

`render()`를 부르는 것: 교사 화면만 바뀌는 조작(자료 서랍 열고 닫기 · 신호등), 수업 중 20초마다 하는 다시 그리기(`tick % 20`), 학생 화면 도구(타이머 · 번호 뽑기), Firebase 소식(내 쓰기의 확인 · 휴대폰 조작), 연결 상태 표시가 바뀔 때.

재현 스크립트(가짜 영상 페이지를 돌려주고 다시 불린 횟수를 셈, 교탁 PC 1536×864):

| 동작 | 고치기 전(이 기기만) | 고치기 전(Firebase + 휴대폰) | 고친 뒤(둘 다) |
| --- | --- | --- | --- |
| 자료 서랍 닫기(교사 화면만 다시 그림) | 1번 | 1번 | 0번 |
| 신호등 누르기(학생 화면 그대로) | 1번 | 2번(쓰기 · 서버 확인) | 0번 |
| 학생 창 위 마우스 움직임 | 0번 | 0번 | 0번 |
| 20초 기다리기(주기 다시 그리기) | 1번 | 1번 | 0번 |
| 타이머 켜기(도구 열기 + 누르기) | 2번 | 3번 | 0번 |
| 휴대폰에서 신호등 | — | 1번 | 0번 |
| 교사 PC 인터넷 3초 끊김 → 다시 연결 | — | 10번 | 0번 |
| 다음 장면으로(자료가 내려감) | 영상 사라짐 | 영상 사라짐 | 영상 사라짐(예전과 같음) |

**고친 것**
- `paint(root, html)`: 학생 화면을 그리는 곳(학생 창 · 한 화면 모드 · `#stage` 기기)은 이것만 써요.
  - 지난번과 같은 내용이면 아무것도 쓰지 않아요(`root.__html`과 비교. 창을 새로 열면 처음부터 그려요).
  - 내용이 달라도 지금 영상 · PDF와 같은 주소의 `iframe`이 같은 자리에 있으면(`keepFrame`), `iframe`은 그대로 두고 둘레만 바꿔요(겹쳐 보이는 타이머 · 번호 뽑기, 연결 표시, 장면 이름). `iframe`은 떼었다 붙이면 다시 불리기 때문에 옮기지 않아요.
  - 다른 자료로 바꾸기 · 내리기 · 다음 장면 · 화면 가리기 · 수업 끝은 예전처럼 화면이 바뀌어요.
- 교사 화면 · 휴대폰 화면은 예전처럼 `innerHTML`로 그려요(`app.__html = null`로 비워 둬요).

## 2. 수업 미리보기가 학생 화면에 보여요

**원인(재현으로 확인)**
학생 창은 교사 화면과 같은 상태 `S`로 그렸어요. `startRehearsal()`이 `S`를 미리보기 상태(`fresh()`)로 바꾸기 때문에, 열려 있는 학생 창에 미리보기 장면 · 자료 · 화면 가리기가 그대로 나갔어요.
미리보기 막대의 ‘다른 기기에 안 보이고 기록 안 됨’과도 어긋났어요. 수업 중에 미리보기를 하면 진행 중인 수업 대신 미리보기가 학생에게 보였어요.
- 고치기 전: 수업 전 미리보기에서 첫 장면 ‘도입 발문’이 학생 창에 나감. 수업 중 미리보기의 화면 가리기(검게)가 학생 창에 나감.

**고친 것**
- `renderStageWin()`: 미리보기 중이면 잠깐 실제 수업 상태(`liveS`)로 학생 창을 그리고(`S` · `rehearsing`을 그리는 동안만 바꿨다가 되돌림) 미리보기는 그리지 않아요. 수업 전이면 ‘수업 시작 전’, 수업 중이면 진행 중인 장면 그대로예요.
- 미리보기 중에는 학생 창을 누르거나(`stage-tap`) 학생 창에서 키를 눌러도 미리보기가 넘어가지 않아요(학생 창은 미리보기를 보여 주지 않으니까요). 학생 창의 F5 막기는 그대로예요.
- 미리보기를 끝내면 교사 화면이 원래 상태(`followS()`)로 돌아오고, 학생 창은 처음부터 바뀐 적이 없어요.

## 3. 한 화면 모드에서 수업을 끝낼 수 없어요

**원인(재현으로 확인)**
‘교사 화면과 학생 화면을 따로 쓰기’를 끄면 `start()`가 PC를 학생 화면 모양(`role = "stage"`)으로 바꿔요. 이 화면의 막대에는 ‘전체 화면 · 수업 준비로’만 있었어요.
마지막 장면에서 다음 키로는 끝나지 않게 되어 있어서(0.7 규칙) 끝낼 길이 없었고, 기록도 남지 않았어요.

**고친 것**
- `viewStage()`: 이 PC가 맡은 한 화면 수업일 때만(`!inPopup && role === "stage" && isHub() && holds()`, 수업 중, 미리보기 아님) 막대의 ‘수업 준비로’ 앞에 ‘수업 끝내기’ 단추를 더해요. 학생 화면 전용 기기 · PC가 연 학생 창에는 없어요.
- 누르면 막대 맨 위 줄에 기존 확인 줄(`endConfirm()`)이 나와요. ‘수업 끝내기’ → 기존 `endLesson()`(기록 · 학생 화면 ‘수업 끝’ · 휴대폰 알림이 발표 모드와 같아요). ‘계속하기’ · Esc · 다음 장면으로 넘기기는 확인 줄을 닫아요.
- 확인 줄이 떠 있는 동안 막대는 사라지지 않아요(`.stage-bar.asking`). 확인 줄은 어두운 색 토큰(`tone-dark`)을 쓰고, 막대의 단추 색 규칙이 덮던 ‘수업 끝내기’ 단추 색만 되돌렸어요.
- 기록 id는 수업 시작 시각으로 만들어서 같은 수업이 두 번 기록되지 않아요(기존 규칙). 끝낸 뒤 막대의 ‘수업 준비로’로 준비 화면에 돌아오고, 다시 시작하면 새 기록이 따로 생겨요.
- 마지막 장면에서 다음 키로 끝나지 않는 보호는 그대로예요.

## 그대로인 것 · 남은 것

- 화면 가리기를 풀면 영상은 처음부터예요(예전 그대로. 가리기는 학생 화면 전체를 바꿔요).
- ‘학생 화면 켜짐’을 다시 눌러 창을 다시 띄우면 창을 새로 그려서 영상이 처음부터예요(예전 그대로).
- PC가 미리보기 중일 때 PIN으로 연결한 휴대폰의 조작은 적용하지 않아요(`applyCmd`, 예전 그대로). 학생 창은 그동안 진행 중인 수업을 보여 줘요.
- 한 화면 모드는 학생도 보는 화면이라 끝낸 뒤 기록을 저절로 띄우지 않아요. 기록은 ‘수업 준비로’ → ‘수업 기록’에서 봐요.
